## 背景与痛点

在日常使用桌面端或网页端 Agent 执行复杂工程任务时，一次交互往往涉及数分钟的深度思考、几十次文件读写与密集的工具链调用。现有的移动端远程方案通常选择将桌面端界面完整映射至手机屏，引发以下实际问题：

- **信息密度失衡**：大量原始推理细节、工具调用入参以及代码差异充满小屏，关键结论被淹没。
- **注意力过度消耗**：外出通勤、就餐或离机休憩时，用户核心诉求仅为确认当前轮次是否结束，并下达下一阶段指令，无暇逐行审查中间步骤。
- **网络与权限适配单一**：纯内网方案出差无法访问，中心化云端转发则引入额外的凭据托管风险。

**极简遥控器**由此设计：手机界面默认仅保留「你的输入」与「AI 最终结论」，彻底屏蔽执行噪声；同时支持随时展开完整轨迹，将注意力支配权交还给用户。

## 核心特性

- 🎛️ **三档按需呈现模式**：提供「单帧」（整屏仅留最新结论，极度清爽）、「聊天」（常规气泡对话流）与「完整」（按原有时序就地展开工具调用与文件差异，支持关键词检索）三档视图，随时无缝切换。
- 📱 **零安装的移动端**：手机端就是一个网页——扫码、用浏览器打开，就是全部。不装 App、不注册账号、不经过任何第三方服务器；可以「添加到主屏幕」，加完那个图标点开是全屏的。
- 🌐 **多通路安全连接**：内置本地局域网（LAN）、Tailscale 私网（支持 MagicDNS 与 HTTPS 证书）以及 Cloudflare 公网隧道（无公网 IP 场景）三种模式，各通道并存且独立提供二维码与访问口令。
- 🐬 **拟人化轻量状态流**：提取步骤之间的关键旁白由鲸鱼娘气泡念出，实时呈现队列刻度尺与计时进度，彻底过滤底层原始推理块。
- 💬 **飞书长连接双向遥控**：基于飞书开放平台 WebSocket 长连接直连桌面端，无需公网 IP 即可实现纯文本交互、选择题回复以及 `/会话` 切换。
- 🗂️ **移动端就地会话治理**：在移动端支持会话重命名、置顶排序、安全归档以及从指定轮次派生新会话（Fork），并明确提示待审批与待回答事件。
- 💻 **桌面端嵌入式「远程窗口」**：在 DSH 桌面端左侧栏提供「远程窗口」快捷入口，点击即在主面板中列出已配对的其他电脑，点一行就能把那一台的 DSH 电脑端界面嵌在面板里；再次点击同一行即可退出并返回原面板。跨机可用，配对步骤见下文「桌面端『远程窗口』」。
- 🔒 **严格的安全与防御边界**：所有接口均实施定长字符串口令校验，防范时序侧信道攻击；配置防暴力破解阈值（1 分钟内试错 5 次锁定 1 分钟）；严禁移动端跨目录读取任意文件；配对信息仅限电脑本机回路读取。

## 快速上手

### 环境依赖

安装前请确认这台电脑满足以下条件：

- **Node.js**：`^22.19.0 || >=24.0.0`
- **DSH（DeepSeek Harness）**：`>=0.1.5-rc.2 <0.3.0`
- **操作系统**：Windows、macOS 或 Linux

> ⚠️ **注意**：DSH 处于活跃迭代期，本插件核心功能在 `0.1.5-rc.2`、`0.1.7-rc.2`、`0.2.0-rc.1` 及 `0.2.0-rc.2` 上完成全量验证。对于低于 `0.1.5` 的历史版本未作兼容承诺；高于 `0.3.0` 的版本存在上游底层接口破坏风险 —— **这一版声明的上界就是 `0.3.0`**，DSH 升上去之后要先等插件跟进，别直接升。

### 安装步骤

#### 途径一：DSH 桌面端图形化安装（推荐）

1. 点击 DSH 顶部导航栏的「插件」按钮进入插件管理页面。
2. 点击页面右上角的「添加插件」按钮打开对话框。
3. 在输入框中输入插件包名 `dsh-mini-remote`（亦可输入 GitHub 仓库地址 `github:xingzhen199186/dsh-mini-remote` 或本地目录路径）。安装源保持默认的「npm 官方源」。
4. 点击对话框底部的「安装」按钮完成安装。

> ⚠️ **注意**：
> 1. **确认来源可信**：插件在本机以当前用户的完整权限运行，来源不明的插件可能损坏 DeepSeek Harness，或读取和泄露敏感数据。
> 2. **暂不支持自动更新**：插件安装后暂不支持自动更新。若需升级版本，请先卸载当前版本后再安装新版本。

#### 途径二：从官方 npm 注册表安装（命令行）

在终端中执行对应的安装命令。命令中的 `web` 为 DSH 默认 Profile 名称，若使用自定义配置档，请替换为对应名称：

```powershell
dsh plugin --profile web add dsh-mini-remote
```

#### 途径三：从 GitHub 仓库直接安装

```powershell
dsh plugin --profile web add github:xingzhen199186/dsh-mini-remote
```

#### 途径四：本地目录安装（开发者调试）

```powershell
dsh plugin --profile web add C:\path\to\dsh-mini-remote
```

### 启动与服务确认

1. 重启 DSH 服务（关闭当前 `dsh web` 窗口并重新运行）。
2. 查看控制台启动日志，插件将输出初始化就绪信息、本机监听端口与动态访问令牌：
   ```text
   [dsh-mini-remote] 已启动：http://127.0.0.1:3090/mini?token=xxxxxxxxxxxx
   ```
3. 打开 DSH 桌面端界面，进入「设置」→ 左侧导航选择「手机遥控」，即可查看配对二维码与连接详情。

> **手机端只有浏览器网页这一种形态。** 扫码用浏览器打开就是全部——没有独立的 App，也没有小程序。可以把这个页面「添加到主屏幕」：加完那个图标点开是全屏的，看着和 App 差不多，跑的仍然是浏览器；换一台手机、或者清掉浏览器数据，就回到重新扫码那一步。
>
> 反过来说，这个网页**也不挑设备**：在 PC 浏览器里打开同一个地址同样能用，而且能在里面开出完整的 DSH 电脑端界面——见「进阶设置：内嵌桌面端界面」。

## 使用示例与配置

### 连接通道对比与选型

依据当前网络拓扑选择最合适的接入通路：

| 通道类型 | 适用场景 | 依赖条件 | 特性与代价 |
| :--- | :--- | :--- | :--- |
| **局域网（LAN）** | 手机与电脑处于同一 Wi-Fi 子网 | 无额外客户端 | 配置即用；脱离当前局域网后立即断开 |
| **Tailscale** | 跨地域移动访问，要求网络地址稳定 | 电脑与手机均安装并登录 Tailscale | 固定私网 IP；可额外申请 Tailscale HTTPS 证书 |
| **公网隧道** | 无公网 IP 且不便安装任何额外客户端 | 需开启 Cloudflare 隧道开关 | 每次重启 DSH 自动更换临时二级域名；初次开启下载约 50 MB 运行组件 |
| **飞书长连接** | 仅依赖企业 IM，完全脱离浏览器 | 配置飞书自建应用机器人凭据 | 无需公网暴露，通过长连接双向收发，支持移动审批 |

### 移动端页面操作指引

- **指令发送与排队**：在底部输入框输入文字并发送。若 Agent 正处于执行中，后续消息自动进入有序队列，并在刻度尺中高亮展示。
- **斜杠指令交互**：输入 `/` 呼出当前会话绑定的系统级指令列表，支持按键过滤与参数提示。
- **多选提问与确认**：当 Agent 发起选项询问时，页面弹出答题卡，支持点选、改选或自定义输入补充文本。
- **回到底部**：在长文本翻阅时，右下角自动浮出「回到底部」悬浮球（单帧模式下不触发）。
- **权限档位切换**：点击顶栏状态区，可在「仅可查看（read-only）」、「工作区内修改（workspace-write）」与「完全权限（danger-full-access）」之间切换。

> ⚠️ **注意**：
> 1. 将权限档位提升至「完全权限」意味着 Agent 具备任意文件与系统级指令执行能力，请务必谨慎操作。
> 2. 系统底层触发的危险命令权限审批弹窗，属于电脑端 DSH 自己的安全边界——手机端没法直接批准，得回电脑上处理。

### 进阶设置：内嵌桌面端界面（手机或 PC 网页）

**手机遥控页不是只能在手机上用。** 在 PC 浏览器里打开同一个地址（扫码打开的那一条），界面一样能用——只是排版是按手机屏幕做的。而让这条路在 PC 上真正好用起来的，是设置里的「进阶设置」：它把完整的 DSH 电脑端界面嵌进来，于是不必额外去开一个 `dsh web`。

怎么打开：

1. 点右上角设置，找到「进阶设置」那一行（提示语是「打开电脑上的 DSH 界面，改那些手机上没有的设置」），切到「开」。
2. 它会再问你一次——**要点第二次才算开**。
3. 下面随即多出一行「电脑端界面」（提示语「电脑端 dsh 完整页面」），点「打开」。
4. 这一页里就嵌进一整屏完整的 DSH 电脑端界面：插件安装、模型配置、会话记录、全量日志都在里面。顶上那条横条可以退出、回到手机遥控页。

**它搬的是这台电脑自己的界面，不是另起一份。** 你在这里改的配置、发的对话，都发生在**这个 DSH 上**——桌面端和它处在同一个状态里。做法也不是"多开一个网页版"：插件的服务端先按官方正门认证一次，然后把每个请求**实时转发**到本机那个界面（连实时的界面刷新都原样转，不攒批）。所以手机全程碰不到任何官方凭据。

> ⚠️ **注意**：
> 1. **这是一个权限开关，不是普通偏好。** 打开它，等于把这个令牌的访问面从"手机页暴露的那点事"扩到**整个电脑端设置面**——模型配置、凭据、插件装卸、会话记录全在内。所以它默认关，而且开着要点两次。
> 2. **如果你的 DSH 压根没带那个网页界面**（只在后台/命令行里跑，从来不在浏览器里打开），这一行就不会出现——与其摆一个点了没反应的开关，不如根本不显示。桌面端和 `dsh web` 两种跑法都自带界面，所以平时它都在，**不需要你为它另外去开一个 `dsh web`**。
> 3. 嵌进来的就是电脑端原样的界面，手机窄屏下做了移动端适配；PC 浏览器上就是原样。

### 桌面端「远程窗口」

**一句话**：在 B 电脑的 DSH 桌面端里，直接打开 A 电脑的 DSH 界面。

**它解决什么**：两台电脑各跑各的 DSH 时，想在一台上看另一台的界面，原来只有两条路——开个浏览器窗口（于是要在两套窗口之间来回切），或者上远程桌面（整块屏幕搬过来，分辨率和快捷键全是麻烦）。这个入口把「那一台」变成主面板里的一屏：点开就是它，再点一下回到原来的面板。

#### 用起来是什么样

1. 点左侧栏的「远程窗口」，主面板列出你配对过的电脑——一行一台，带名字、地址、最近一次连上的时间。
2. 点其中一行，那一台的界面就嵌在面板里。
3. 再点一下左侧栏那一行（点图标、点文字、点整行空白都算），退出，回到进入前那个面板。

界面正常显示时顶上那行横条会**自动收起**，鼠标碰一下屏幕顶部就滑出来。横条里是「← 返回列表」、这是哪一台、以及「再试一次」——出问题时它是唯一的出口（和换条路重试的入口），所以正在换票、出错、框一直没打开这几种状态下它**不会收起**，一直在。

#### 安全上做了什么

- **凭据不过手**：打开窗口时，服务端当场签一张一次性票据（30 秒内有效、只能兑一次）。浏览器拿到的是这张票，**访问口令和长期凭据一个字节都不进浏览器**——既不留进浏览历史，也不进被嵌进来的那个页面。
- **只有带有效票据的页面才允许被嵌**：跨站嵌入默认禁止，带票的那一次才放开。外部页面即使拿到地址也进不来。
- **撤销是立即的**：在 A 的设置里撤销 B 这台设备之后，B 已经开着的窗口下一次请求就过不去，不需要等它自己断。
- **跟着 DSH 一起失效**：A 的 DSH 重启，那一屏的通行凭据自动作废，重新点一次就能再进。

#### 跨机使用（两台电脑）

下面把被连的那台电脑叫 A，去连的那台叫 B。

**A 侧**

1. **装本插件，版本不低于 `0.2.1`。**「远程窗口」是 `0.2.1` 才有的功能——B 连的是 A 上跑着的那份代码，A 装的是旧版，B 看到的就还是旧界面。
2. 打开「设置 → 手机遥控 → 允许别的电脑连接」，把这个开关打开。它默认是关的；关着的时候，A 连配对请求也不受理。
3. 在同一个设置页的「密码」那一块点「复制」，取出 A 的口令。

**B 侧**（在 B 的「设置 → 手机遥控」里操作）

要用的那一块叫「其他电脑」，在设置页靠下。它和上面那块「设备」正好相反：那块是「谁进得来」，这块是「我连得上谁」。

1. 点「添加一台电脑」，摊开三个框。
2. **那台电脑的地址（它「手机遥控」页那条，不带 `/mini`）**：填 A 的地址。这一格填什么最关键，见下面「地址填哪一条」。
3. **那台电脑的口令（在它的「手机遥控」设置里复制）**：填 A 侧第 3 步复制来的那串。这一格是打码的。
4. **给它起个名字（可留空，留空就用地址当名字）**：方便你在名单里认出是哪一台。
5. 点「确认添加」。这一步会真的去 A 那边配一次对——成功之后 A 的设置页会多出一条「这台电脑」的记录，B 这边多出一行。
6. 点名单里那一行。

名单每一行显示：名字、地址、`最近成功 <时刻>`（没连成过就是「还没有记录」），右边两枚按钮——**「重连」**重新取一次通行凭据，**「断开」**删掉这条配对。断开前会问你一次，并说明对面那台电脑上的记录**还留着**；要彻底收回，得去 A 那边把这一台撤销。

**地址填哪一条**

- 填 A 的「手机遥控」页里那条地址（末尾不用带 `/mini`）；**不要**填你在 A 上打开 DSH 界面时用的那条。
- **必须 `https://`。** 明文 `http://` 能配对、也能取到通行凭据，但框里是白的——那枚通行凭据在非 https 的地址上会被浏览器丢掉。
- 推荐走 Tailscale：在 A 上打开「HTTPS 地址（Tailscale）」开关，B 填 `https://<机器名>.<你的 tailnet>.ts.net`，**不用写端口**。地址固定，设一次就完事。
- 「公网访问」隧道那条地址每次重启都会变，不适合跨机。

**怎么知道做对了**

点名单里那一行，框里出现那台电脑的界面。出问题时那一行底下会有说明——对面没开开关、被撤销了、连不上、地址填错，各有各的说法，照着改就行。

**以后要收回某一台的权限**

在 A 的「设置 → 手机遥控 → 设备」那一块——就是列出「谁进得来」的那份名单，每行带「改名」和「撤销」——找到那台电脑，点「撤销」，再点「确认撤销」。**立即生效**：对面已经开着的窗口，下一次请求就过不去，不用等它自己断。

### 飞书机器人配置流程

1. 登录 [飞书开放平台](https://open.feishu.cn/) 创建企业自建应用。
2. 记录「凭证与基础信息」中的 `App ID` 与 `App Secret`。
3. 进入「添加应用能力」页面，添加「机器人」能力。
4. 进入「事件与回调」页面，配置事件订阅方式为「使用长连接接收事件」，并添加 `im.message.receive_v1` 事件。
5. 进入「权限管理」页面，检索并开通以下 3 项权限：
   - 接收消息（`im:message:receive_v1`）
   - 以应用身份发消息（`im:message:send_as_bot`）
   - 获取与发送单聊、群组消息（`im:message.group_at_msg:readonly` 等对应集合）
6. 创建并**发布应用版本**。
7. 返回 DSH 桌面端「设置」→「手机遥控」→「飞书」栏目，填入凭证并启用开关。首次交互机器人将在单聊中返回用户的 `open_id`，将其复制填入白名单保存后即可正常通讯。

### 核心配置参数表

配置项支持在 DSH 标准配置文件中声明，亦可通过桌面端「手机遥控」界面配置：

| 参数项 | 数据类型 | 默认值 | 生效方式 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `port` | `number` | `3090` | 重启生效 | 遥控服务监听的本地 HTTP 端口（冲突时自动顺延） |
| `token` | `string` | *(随机生成)* | 重启生效 | 访问口令（支持手动修改，长度不得低于 12 位） |
| `defaultMode` | `string` | `"minimal"` | 即时生效 | 移动端默认呈现视图：`"minimal"`、`"chat"`、`"full"` |
| `externalNotify` | `boolean` | `true` | 即时生效 | 任务完成时是否触发系统通知音效与设备震动 |
| `tunnel.enabled` | `boolean` | `false` | 重启生效 | 是否启用 Cloudflare 临时公网隧道 |
| `tailscale.serve` | `boolean` | `false` | 重启生效 | 是否尝试配置并监听 Tailscale 专有 HTTPS 证书通道 |
| `feishu.enabled` | `boolean` | `false` | 即时生效 | 是否开启飞书应用长连接双向通道 |
