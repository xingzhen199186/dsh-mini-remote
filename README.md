**极简遥控器**适应多种使用场景：离开电脑时，通过移动端网页版操作电脑上的 DSH；在另一台电脑上，通过远程窗口操作核心设备上的完整 DSH 界面，同时支持设置 A/B 端跨机任务，由 A 端 DSH 在授权范围内操作 B 端的文件和命令，省去在另一台电脑上重新配置 DSH 及各种插件的麻烦。

## 功能概览

- 🎛️ **三种对话视图**：「单帧」整屏保留最新结论，「聊天」按气泡排列历史，「完整」在原有时序中展开工具调用与文件差异，并支持检索已加载的轨迹。
- 📱 **手机浏览器直接使用**：扫码即可打开，无需安装 App 或注册账号；可「添加到主屏幕」，更换手机或清除浏览器数据后需要重新配对。
- 🌐 **多种连接通道**：支持局域网（LAN）、Tailscale 私网与 HTTPS、Cloudflare 公网隧道，以及飞书长连接。各通道的网络边界不同，详见「安全边界」。
- 🐬 **轻量状态反馈**：显示关键旁白、耗时和排队状态；原始思考过程不会进入手机对话区。
- 🗂️ **移动端会话管理**：支持会话重命名、置顶、归档、从指定轮次派生新会话（Fork），并提示待审批与待回答事件。
- 🖥️ **A 端使用 B 端**：A 端保留会话和模型，通过 `b_*` 工具读取或修改 B 端文件；B 端本地决定授权目录以及写入、文件夹管理和命令权限。
- 🗂️ **B 项目**：在 A 端为 B 端真实目录建立工作区入口，提供 B 文件面板和项目专用的「新建 B 会话」。
- 💻 **远程窗口**：在另一台电脑的 DSH 桌面端嵌入本机完整界面；该功能与 A/B 端文件任务的方向和用途不同，详见「PC 端远程窗口」。
- 💬 **飞书双向遥控**：通过飞书 WebSocket 长连接进行纯文本交互、选择题与审批回复，以及 `/会话` 切换。
- 🔒 **设备级访问控制**：手机与电脑分别登记、可单独撤销；配对信息仅限本机读取，口令校验有试错限速。高权限功能和公网暴露仍有明确风险，不应视为公网安全保证。

## 安装

### 环境依赖

安装前请确认这台电脑满足以下条件：

- **Node.js**：`^22.19.0 || >=24.0.0`
- **DSH（DeepSeek Harness）**：`>=0.1.5-rc.2 <0.3.0`
- **操作系统**：Windows、macOS 或 Linux

> ⚠️ **版本说明**：DSH 处于活跃迭代期。本插件核心功能曾在 `0.1.5-rc.2`、`0.1.7-rc.2`、`0.2.0-rc.1` 与 `0.2.0-rc.2` 上做过全量验证；0.2.5 的发版记录还包括在 **DSH `0.2.1-rc.3`** 上的兼容性检查（结果 `COMPATIBLE`）、宿主自检与 B 端预设注册，并使用该版本的 `dsh-tools` 完成测试。低于 `0.1.5` 的版本未作兼容承诺；高于或等于 `0.3.0` 的版本存在上游接口破坏风险。插件声明上界为 `<0.3.0`，升级 DSH 前应先确认插件跟进情况。

### 安装步骤

#### 途径一：DSH 桌面端图形化安装（推荐）

1. 点击 DSH 顶部导航栏的「插件」按钮进入插件管理页面。
2. 点击页面右上角的「添加插件」按钮打开对话框。
3. 在输入框中输入插件包名 `dsh-mini-remote`（亦可输入 GitHub 仓库地址 `github:xingzhen199186/dsh-mini-remote` 或本地目录路径）。安装源保持默认的「npm 官方源」。
4. 点击对话框底部的「安装」按钮完成安装。

> ⚠️ **注意**：
> 1. **确认来源可信**：插件在本机以当前用户的完整权限运行，来源不明的插件可能损坏 DeepSeek Harness，或读取和泄露敏感数据。
> 2. **暂不支持自动更新**：插件安装后暂不支持自动更新。若需升级版本，请先卸载当前版本后再安装新版本。

#### 途径二：从官方 npm 注册表安装（命令行）

在终端中执行对应的安装命令。命令中的 `web` 为 DSH 默认 Profile 名称，若使用自定义配置档，请替换为对应名称：

```powershell
dsh plugin --profile web add dsh-mini-remote
```

#### 途径三：从 GitHub 仓库直接安装

```powershell
dsh plugin --profile web add github:xingzhen199186/dsh-mini-remote
```

#### 途径四：本地目录安装（开发者调试）

```powershell
dsh plugin --profile web add C:\path\to\dsh-mini-remote
```

### 启动与服务确认

1. 重启 DSH 服务（关闭当前 `dsh web` 窗口并重新运行）。
2. 查看控制台启动日志，插件将输出初始化就绪信息、本机监听端口与动态访问令牌：
   ```text
   [dsh-mini-remote] 已启动：http://127.0.0.1:3090/mini?token=xxxxxxxxxxxx
   ```
3. 打开 DSH 桌面端界面，进入「设置」→ 左侧导航选择「遥控设置」，即可查看配对二维码与连接详情。

> **手机端只有浏览器网页这一种形态。** 扫码并用浏览器打开即可，没有独立 App 或小程序。页面可以「添加到主屏幕」，图标打开时为全屏显示，实际仍由浏览器运行。更换手机或清除浏览器数据后，需要重新扫码配对。
>
> 同一地址也能在 PC 浏览器中打开；开启「进阶设置」后，还可在其中使用完整的 DSH 电脑端界面，见「进阶设置：内嵌桌面端界面」。
>
> **怎样确认启动成功**：设置页出现「遥控设置」标题、连接地址与二维码；控制台出现 `[dsh-mini-remote] 已启动` 行。若只有控制台输出而设置页为空，先刷新或重启 DSH，再检查「自检」。

## 手机连接与使用

### 连接通道对比与选型

依据当前网络拓扑选择最合适的接入通路：

| 通道类型 | 适用场景 | 依赖条件 | 特性与代价 |
| :--- | :--- | :--- | :--- |
| **局域网（LAN）** | 手机与电脑处于同一 Wi-Fi 子网 | 无额外客户端 | 配置即用；脱离当前局域网后立即断开 |
| **Tailscale** | 跨地域移动访问，要求网络地址稳定 | 电脑与手机均安装并登录 [Tailscale](https://tailscale.com/download) | 固定私网 IP；可额外申请 Tailscale HTTPS 证书 |
| **公网隧道** | 无公网 IP 且不便安装任何额外客户端 | 需开启 Cloudflare 隧道开关 | 每次重启 DSH 自动更换临时二级域名；初次开启下载约 50 MB 运行组件 |
| **飞书长连接** | 仅依赖企业 IM，完全脱离浏览器 | 配置飞书自建应用机器人凭据 | 无需公网暴露，通过长连接双向收发，支持移动审批 |

### 第一次连接手机

1. 在电脑上安装并启用本插件，重启 DSH 服务。
2. 打开 DSH 桌面端「设置」→「遥控设置」。最上方的「手机连接」分组默认展开，列出这台电脑当前可用的地址，例如「本机」「内网」「Tailscale」「Tailscale（加密）」「公网访问」。实际出现哪几条，取决于本机安装和开启了哪些通道。
3. 选择手机能够访问的一条通道。手机与电脑在同一 Wi-Fi 时优先用「内网」；需要跨网络访问时使用 Tailscale 或公网隧道。
4. 用手机浏览器扫描对应二维码，或复制地址后在手机浏览器打开。
5. 页面打开后，可在浏览器菜单中选择「添加到主屏幕」，以后从图标进入。
6. 回到电脑的「遥控设置」→「电脑与设备」，展开「设备」列表，应能看到刚刚登记的手机。

**怎样确认连接成功**：手机页面不再停留在「连接中」或密码输入页，能够显示会话列表与当前会话；电脑的设备列表新增该手机记录。设备记录首次扫码时自动登记，后续不必每次扫码。

地址形如：

```text
http://192.168.1.2:3090/mini?token=xxxxxxxxxxxx
```

设置页中每条地址的二维码固定为 **160×160**，右侧地址框与「复制」按钮位于同一行；点击地址框会全选整条地址。

> ⚠️ **该地址含入场口令。** 持有者可以为自己的设备完成配对并操作本机，因此不得截图外发或粘贴到公开位置。浏览器配对后会改用设备凭据，但地址本身仍应按凭据保管。更换口令后需要重启 DSH，并重新扫码。

手机页面支持以下操作：

- **发送与排队**：在底部输入框发送消息；Agent 正在执行时，后续消息按顺序进入队列，并显示在队列刻度上。
- **斜杠指令**：输入 `/` 打开当前会话的指令列表，支持过滤和参数提示。
- **提问与审批**：Agent 发起选择题时显示答题卡，可点选、改选或补充文字；需要确认工具或命令时显示审批卡，可选择「同意」或「拒绝」。
- **回到底部**：翻阅长内容后，右下角出现「回到底部」浮标；单帧模式不显示。
- **权限档位**：在「仅可查看（read-only）」「工作区内修改（workspace-write）」与「完全权限（danger-full-access）」之间切换。「完全权限」需要二次确认。
- **会话管理**：重命名、置顶、归档和派生新会话（Fork）。

> ⚠️ **注意**：
> 1. 「完全权限」允许 Agent 修改任意文件并执行系统命令，只应在明确了解后果时开启。
> 2. 手机可处理已推送到页面的审批；未推送、已超时或需要更多上下文的审批，仍需回到电脑处理。
> 3. 网络中断或页面关闭期间，审批可能自动退回电脑。以页面或电脑端实际提示为准。

### 进阶设置：内嵌桌面端界面（手机或 PC 网页）

手机页面也能在 PC 浏览器中打开，只是排版按手机屏幕设计。开启设置中的「进阶设置」后，可以在同一页面内使用完整的 DSH 电脑端界面，无需另外启动一个 `dsh web`。

操作步骤：

1. 在手机或 PC 页面右上角打开设置，找到「进阶设置」，提示语为「打开电脑上的 DSH 界面，改那些手机上没有的设置」。
2. 将开关切到「开」，并按页面提示再次确认。该功能需要两次确认才会开启。
3. 展开后点击「电脑端界面」旁的「打开」。
4. 页面内会出现完整的 DSH 电脑端界面，包括插件安装、模型配置、会话记录和全量日志。顶部横条可退出并返回手机页面。

**该界面属于同一个 DSH 实例，不是第二份环境。** 在其中修改的配置和发起的对话都作用于当前 DSH，桌面端与页面共享同一状态。插件服务端先通过官方入口认证，再把请求实时转发到本机界面，包括实时界面刷新；手机端不会取得官方凭据。

> ⚠️ **注意**：
> 1. **这是权限开关，不是普通外观偏好。** 开启后，当前访问凭据的作用范围会从手机页面扩展到整个电脑端管理面，包括模型配置、凭据、插件装卸和会话记录。该开关默认关闭，开启时需要二次确认。
> 2. 嵌入的是原样电脑端界面；手机窄屏下做了移动端适配，PC 浏览器中保持原布局。关闭开关后，该入口停止提供完整界面。

## PC 端远程窗口

远程窗口用于在另一台电脑（B）的 DSH 桌面端直接打开核心电脑（A）的完整 DSH 界面，不必在浏览器窗口之间来回切换，也不必使用远程桌面。它用于查看和操作 A 的界面，与「A 端使用 B 端」中的文件和命令任务不是同一条路径。

### 用起来是什么样

1. 在 B 的 DSH 桌面端左侧栏点击「远程窗口」，主面板会列出已经配对的电脑。
2. 点击名单中的一行，A 的完整 DSH 界面就会嵌入当前面板。
3. 顶部横条提供「← 返回列表」、当前电脑名称和「再试一次」。界面正常显示时，横条会自动收起，鼠标移到屏幕顶部即可重新展开；连接中、出错或界面未打开时，横条会保持显示。
4. 再次点击左侧栏「远程窗口」即可退出，回到进入前的面板；也可以通过顶部横条返回名单。

### 安全边界

- 打开窗口时，A 会签发一张 **30 秒内有效、只能兑换一次**的票据。访问口令和长期凭据不会进入浏览器。
- 跨站嵌入默认禁止，只有携带有效票据的页面才允许嵌入。
- 在 A 的设备名单中撤销 B 后，B 已经打开的窗口会在下一次请求时失效。
- A 的 DSH 重启后，原窗口的通行票据会失效；重新点击远程窗口可取得新票据。
- 远程窗口展示的是 A 的完整管理面，包括会话、模型配置和插件管理。只应向可信电脑开放「允许别的电脑连接」。

### 作为 A 端（被连接的电脑）

1. 打开「设置」→「遥控设置」→「电脑与设备」，开启「允许别的电脑连接」。该开关默认关闭，关闭时不受理配对和取票请求。
2. 在「手机连接」中复制访问口令，供 B 配对使用。

### 作为 B 端（发起连接的电脑）

1. 打开「设置」→「遥控设置」→「电脑与设备」→「其他电脑」，点击「添加一台电脑」。
2. 填写 A 的地址和访问口令，并为这台电脑起一个便于识别的名字；名称留空时使用地址。
3. 点击「确认添加」。成功后，A 的设备名单会新增这台 B，B 的「其他电脑」中也会出现对应记录。
4. 点击名单中的那一行，或通过左侧栏「远程窗口」选择 A。

「其他电脑」与「设备」的方向相反：「设备」记录谁可以连入本机，「其他电脑」记录本机可以连向谁。断开「其他电脑」只删除本机侧记录，不会撤销 A 设备名单中的授权。

### 地址填哪一条

- 填写 A 的「遥控设置」页提供的连接地址，**不带 `/mini` 或其后的参数**；不要填在 A 上打开 DSH 界面时使用的地址。
- 跨机地址必须使用 `https://`。本机回环地址 `127.0.0.1`、`localhost` 或 `[::1]` 是例外，可在本机自测时使用 `http://`。
- 推荐在 A 的「外部访问」中开启「HTTPS 地址（Tailscale）」，B 填写 `https://<机器名>.<tailnet>.ts.net`，不需要写端口，地址也更稳定。
- 公网隧道地址每次重启 DSH 都会变化，不适合作为固定的跨机入口。

### 怎么确认连接成功

在 B 的名单中点击 A 后，面板内应出现 **A 的完整 DSH 界面**，而不是空白页或一直停留在 `Loading plugins…`。如果只看到空白或加载提示，先按「排障」检查地址、票据和 Tailscale Serve 配置。

### 怎么收回权限

在 A 的「设置」→「遥控设置」→「电脑与设备」→「设备」中找到 B，点击「撤销」并再次确认。撤销立即生效：B 已经打开的窗口会在下一次请求时被拒绝，需要重新配对才能恢复。

## A 端使用 B 端

这部分介绍一条与手机页面、远程窗口都不同的路径：**A 端运行会话和模型，A 端的 Agent 通过 `b_*` 工具操作 B 端的真实文件。** 两端都需要安装本插件。

### 两个角色分别做什么

A、B 表示一次跨机协作中的方向，不表示两种互斥的安装包，也不要求在两台电脑之间二选一。

| 角色 | 在设置页中的入口 | 负责什么 | 不负责什么 |
| :--- | :--- | :--- | :--- |
| **A 端** | 「A/B 端协作」→「作为 A 端」 | 保留会话、模型和插件，发起 B 端任务，查看在线状态与授权目录 | 不能替 B 端选择目录或扩大权限；B 端的文件不会复制到 A 端 |
| **B 端** | 「A/B 端协作」→「作为 B 端」 | 接受 A 端任务，在本地提供文件、文件夹操作或命令执行能力 | 不接收 A 端的会话和模型；授权目录、写入、管理和命令权限均由 B 端本地决定 |

**关键区别**：A 端会话里的 `read`、`write`、`edit`、`bash` 等本地工具作用于 **A 端**；只有 `b_list`、`b_read`、`b_write`、`b_shell` 等 `b_*` 工具作用于 **B 端**。任务涉及另一台电脑时，应在指令中明确写出 `b_*` 和 B 端路径。

### 第一次配对与验证

**A 端操作**

1. 在 A 端安装本插件并重启 DSH。
2. 打开「设置」→「遥控设置」→「A/B 端协作」，展开「作为 A 端」，打开总开关。
3. 在「B 端要填的地址」中选一条 B 端能访问的地址。默认服务端口为 `3090`，地址不要带 `/mini`。
4. 点击「生成配对码」，得到 6 位数字。配对码 10 分钟内有效，成功使用一次后失效。
5. 先保持写入、文件夹管理和命令权限关闭，完成只读验证后再逐项开启。

**B 端操作**

1. 在 B 端安装同一版本的插件并重启 DSH。
2. 打开「设置」→「遥控设置」→「A/B 端协作」→「作为 B 端」。
3. 填写 A 端地址、6 位配对码，并在「授权给 A 的文件夹」中写入 B 端的绝对路径，一行一个。首次验证建议使用专用测试目录，不要授权整个磁盘。
4. 保持「允许 A 写这些文件夹」「允许 A 建目录、移动、复制、删除」「允许 A 在这台电脑上执行命令」全部关闭。
5. 点击「配对并开启」。

**怎样确认配对成功**

- B 端「作为 B 端」显示「已连上 A，等待任务」，并显示最近一次成功轮询时间。页面每 5 秒自动刷新一次状态，配对后不需要手动刷新。
- A 端「作为 A 端」的名单中出现该 B 端电脑，状态为「在线」，授权目录与 B 端填写内容一致。
- 若 B 端仍显示「还没连上 A」，先按 `Ctrl+F5` 强制刷新；仍不成功时按「排障」检查地址、总开关、端口与网络。

### 在 A 端执行 B 端文件任务

先做只读验证。在 A 端任一会话中发送类似指令：

```text
用 b_list 列出 B 端 D:\b-agent-test 下的文件，再用 b_read 读取其中一个文本文件，并说明文件名和内容。
```

预期结果是列出 B 端目录并返回 B 端文件内容。可以用一个 A、B 同名但内容不同的文件作对照，确认读取的不是 A 端本地文件。

确认只读结果正确后，再按需开启 B 端权限：

| B 端开关 | 允许的 `b_*` 操作 | 风险边界 |
| :--- | :--- | :--- |
| 授权目录（默认必填） | `b_list`、`b_read`，以及授权目录内的路径访问 | 路径必须位于授权目录内，不使用 `..` 或指向目录外的链接 |
| 允许 A 写这些文件夹 | `b_write` | 可修改授权目录内已有文件 |
| 允许 A 建目录、移动、复制、删除 | `b_mkdir`、`b_copy`、`b_move`、`b_delete` | 可改变授权目录结构；删除不可恢复 |
| 允许 A 在这台电脑上执行命令 | `b_shell`、`b_terminal_*` | **影响范围不限于授权目录**，等于把整台电脑的命令执行能力交给 A 端的 Agent |

删除、移动等操作会要求模型携带 `confirm`，这属于模型层的二次确认，不是人工审批。真正的授权边界仍由 B 端设置页上的本地开关决定。A 端不得替 B 端修改这些开关。

写入验证可在开启写权限后进行：

```text
用 b_write 在 B 端 D:\b-agent-test\b-test.txt 写入“来自 A 的写入”，然后读回确认。
```

检查 B 端磁盘上出现该文件、内容正确，而 A 端相同路径没有生成文件。之后应关闭不再需要的写权限或命令权限。

> ⚠️ **多台 B 端电脑**：只有一台 B 端在线时，`b_*` 可以省略目标参数。多台同时在线时，工具可能要求指定目标；当前设置页名单显示名称、在线状态和授权目录，但不提供可复制的手工 id。为避免任务落到错误电脑，验证阶段应只保留目标 B 端在线，或先断开其他 B 端。
>
> **撤销协作**：在 A 端「作为 A 端」的名单中撤销某台 B 端后，需要在 A 端重新生成配对码并重新配对；关闭 A 端「作为 A 端」总开关会停止接受配对和任务。

### B 端身份与重新配对

B 端会在插件数据目录中生成并保存 `machine-id`。重新配对时，B 端把这个稳定标识交给 A 端，A 端据此复用原记录：设备名、授权目录和权限按本次配对更新，**旧 token 立即失效，名单中不会新增一条重复记录**。

- 插件升级、重装后如果原数据目录仍在，`machine-id` 会继续复用。数据目录被删除后，该标识也会消失，此时 A 端会把它当作新设备。
- 由不支持 `machine-id` 的旧版本留下的记录无法自动匹配，即使来自同一台 B 端也不会复用。需要在 A 端「作为 A 端」的名单中手动撤销旧记录。
- B 端授权目录或权限发生变化时，应重新配对，而不是在 A 端直接猜测或填写 B 端路径。

## B 项目

B 项目把 B 端的一个真实目录登记为 A 端的 DSH 工作区。A 端只保存一个「门牌目录」和路径映射，**不复制 B 端文件**；真实文件始终位于 B 端。

A 端的原生文件树中是门牌占位目录，不是 B 端的文件内容。查看和修改 B 端项目文件应使用 B 文件面板或该项目的 B 会话。

### 建项目并选择 B 目录

前置条件：A 端「作为 A 端」已开启，B 端「作为 B 端」在线；B 端至少有一个授权目录。

1. 在 A 端打开「设置」→「遥控设置」→「A/B 端协作」→「B 项目」。
2. 点击「新建 B 项目」。新建表单默认收起，展开后填写项目名称。
3. 点击「选择 B 文件夹」。选择器从 B 端的授权根开始，顶部固定显示当前目录，可逐层进入；底部左侧显示完整路径，右侧是「就选这个目录」。
4. 如需新建目录，使用「＋ 新建文件夹」。该操作要求 B 端已开启文件夹管理权限；也可以先在 B 端手动建好目录。
5. 选中目录后点击「新建 B 项目」。

**怎样确认创建成功**：B 项目列表出现该项目，并显示 B 端完整路径；A 端工作区列表出现「B · 项目名」。工作区未立即出现时，刷新 DSH 后重试。A 端不会复制 B 端文件，项目创建完成也不代表文件已同步。

> ⚠️ 一个 B 端目录只能登记为一个 B 项目；B 端目录不存在且 A 端没有文件夹管理权限时，创建会失败。移除 B 项目只删除 A 端的门牌和工作区，**不删除 B 端真实文件**。

### 新建 B 会话

1. 在「B 项目」列表中找到目标项目。
2. 点击「新建 B 会话」。
3. 会话创建后会自动尝试打开；若界面未自动打开，到左侧「B · 项目名」工作区中打开。
4. 该会话从创建时即使用「B 端执行」预设，项目内的本地文件与命令工具被移除，文件操作应走 `b_*`。
5. 会话默认以项目根为工作目录；不写路径时从项目根开始，相对路径按项目根展开，项目外的绝对路径会被拒绝。

**怎样确认会话正确**：会话名称出现在「B · 项目名」工作区，且预设为「B 端执行」。让 Agent 列出项目根目录时，返回内容应来自 B 端，而不是 A 端门牌目录。

### 浏览 B 文件

1. 在「B 项目」列表点击「浏览 B 文件」。
2. 面板从项目根开始列出 B 端目录和文件，并显示文件大小。
3. 点击目录进入下一级；点击文本文件可查看内容。顶部提供「刷新」「重读文件」和「收起文件面板」。
4. 文件面板只负责浏览和读取；需要写入时，在 B 会话中明确调用 `b_write`，并确保 B 端已开启写权限。

> ⚠️ B 文件面板与 B 会话都只允许访问该项目根目录内的路径。项目外路径应另建 B 项目，不能通过 `..` 或绝对路径绕过。

## 设置页说明

设置页入口为 DSH「设置」→「遥控设置」。0.2.5 起按六组排列：

| 分组 | 主要内容 | 默认状态 |
| :--- | :--- | :--- |
| **手机连接** | 地址、二维码、访问口令 | 默认展开 |
| **外部访问** | Tailscale、HTTPS 地址、公网隧道 | 默认展开 |
| **电脑与设备** | 允许别的电脑连接、设备名单、其他电脑 | 分组展开；设备名单默认收起 |
| **A/B 端协作** | 作为 A 端、作为 B 端、B 项目 | 默认收起 |
| **飞书** | 机器人凭据、白名单、配置指引 | 默认收起；配置指引也默认收起 |
| **自检** | 版本、接口、开关、最近错误 | 默认收起，位于页面最末 |

折叠状态只影响本次设置页显示，不作为权限开关。分组收起不代表相关功能关闭。

### 手机连接与外部访问

- 每条连接地址均显示 160×160 二维码，地址框与「复制」按钮在同一行。
- 「手机连接」管理本机地址与访问口令；「外部访问」管理 Tailscale、Tailscale HTTPS 和 Cloudflare 公网隧道。
- Tailscale 的 HTTPS 地址与普通 Tailscale 地址指向同一服务，区别仅在连接是否加密；公网隧道每次重启 DSH 后地址会变化。
- 更换访问口令需要重启 DSH 后生效，之后手机需要重新扫码。

### 电脑与设备

- **允许别的电脑连接**：默认关闭。关闭时不受理其他电脑的配对和取票请求。
- **设备**：默认收起。展开后可查看已登记的手机或电脑，逐台改名或撤销；撤销需要二次确认，撤销后该设备必须重新扫码。
- **清理 30 天未使用**：只清理创建时间和最近使用时间**都早于 30 天**的记录。最近 30 天内出现过的重复设备不会被清理；清理后相关设备需要重新扫码。
- **其他电脑**：列出本机可以连接的其他电脑，与「设备」方向相反。「设备」回答谁可以连入本机，「其他电脑」回答本机可以连向谁。断开一条「其他电脑」记录只删除本机侧记录，对方保留的授权仍需到对方设备名单中撤销。

远程窗口的完整教程、地址要求和安全边界见 [PC 端远程窗口](#pc-端远程窗口)。

### A/B 端协作

- 「A/B 端协作」分组默认收起，展开后依次为「作为 A 端」「作为 B 端」「B 项目」。
- B 端页面每 5 秒自动读取一次本机状态，配对成功后不需要手动刷新。
- B 端仍显示「还没连上 A」时，界面会提示尝试 `Ctrl+F5` 强制刷新。完成一次成功轮询后，状态应变为「已连上 A，等待任务」。
- B 端重新配对时，A 端优先按持久 `machine-id` 复用原记录，旧 token 立即失效；来自无 `machine-id` 旧版本的记录需要在 A 端手动撤销。
- B 项目的新建表单默认收起，创建成功后才清空并收起。

### 飞书机器人配置流程

飞书分组和组内「配置指引（飞书后台六步）」都默认收起。

1. 登录 [飞书开放平台](https://open.feishu.cn/)，创建企业自建应用。
2. 在「凭证与基础信息」中取得 `App ID` 与 `App Secret`。
3. 在「添加应用能力」中添加「机器人」能力。
4. 在「事件与回调」中选择「使用长连接接收事件」，并添加 `im.message.receive_v1` 事件。
5. 在「权限管理」→「应用身份权限」中开通以下 3 项：
   - 接收发给机器人的消息：`im:message:receive_as_bot`
   - 以应用身份发消息：`im:message:send_as_bot`
   - 回复消息：`im:message`
6. 创建并**发布应用版本**。修改过能力、权限或事件后都必须重新发布。
7. 回到「设置」→「遥控设置」→「飞书」，填写 `App ID`、`App Secret` 并保存，再打开开关。
8. 在飞书单聊中给机器人发送一条消息。两个白名单都为空时，任何来源都不会被接受；页面或机器人回复会显示来源的 `open_id`（可能还有 `chat_id`）。
9. 将 `open_id` 填入「允许的 open_id」并保存，再发送一次消息即可正常使用。

> ⚠️ 本版只处理单聊，不处理群聊。`App Secret` 保存后不再回显，留空保存表示不修改原值。白名单为空时默认拒绝所有来源。

### 核心配置参数表

配置项支持在 DSH 标准配置文件中声明，亦可通过桌面端「遥控设置」界面配置：

| 参数项 | 数据类型 | 默认值 | 生效方式 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `port` | `number` | `3090` | 重启生效 | 遥控服务监听的本地 HTTP 端口（冲突时自动顺延） |
| `token` | `string` | *(随机生成)* | 重启生效 | 访问口令（支持手动修改，长度不得低于 12 位） |
| `defaultMode` | `string` | `"minimal"` | 即时生效 | 移动端默认呈现视图：`"minimal"`、`"chat"`、`"full"` |
| `externalNotify` | `boolean` | `true` | 即时生效 | 任务完成时是否触发系统通知音效与设备震动 |
| `tunnel.enabled` | `boolean` | `false` | 重启生效 | 是否启用 Cloudflare 临时公网隧道 |
| `tailscale.serve` | `boolean` | `false` | 重启生效 | 是否尝试配置并监听 Tailscale 专有 HTTPS 证书通道 |
| `feishu.enabled` | `boolean` | `false` | 即时生效 | 是否开启飞书应用长连接双向通道 |

### 自检

自检位于设置页最末，默认收起，只允许本机读取，不包含口令或密钥。展开后可以核对：

- 插件版本、宿主进程启动时间和代码文件时间；进程比代码旧时会显示警告。
- 已注册接口及当前挂载状态。
- 手机服务是否在监听，以及实际端口。
- 「允许别的电脑连接」等开关状态。
- 最近错误摘要（最新在前，最多 20 条，重启后清空）。

**判据**：版本显示为当前安装版本，手机服务处于监听状态，所需接口没有被标记为「现在不在」；若进程启动时间早于代码修改时间，应重启 DSH。

## 排障

排障按「症状 → 检查 → 恢复判据」进行。先确认故障发生在哪一层，再修改配置；重复配对通常只会增加无关记录。

### B 端显示「还没连上 A」

1. 等待至少 5 秒。B 端状态每 5 秒自动刷新，配对响应只代表点击配对的那一刻。
2. 按 `Ctrl+F5` 强制刷新 B 端页面或 DSH 窗口，排除旧页面快照。
3. 检查 B 端填写的 A 端地址是否为 A 端「B 端要填的地址」原文，不带 `/mini`，端口与 A 端自检显示的实际端口一致。
4. 在 B 端浏览器中打开 A 端手机页或最小访问地址，验证网络是否可达。
5. 检查 A 端「作为 A 端」总开关、B 端「作为 B 端」开关，以及 A 端防火墙是否拦截 Tailscale 或局域网地址。
6. 查看 B 端「最后一次错误」和 A 端「自检」→「最近错误」。

**恢复判据**：B 端显示「已连上 A，等待任务」和新的成功轮询时间；A 端名单中的 B 端状态变为「在线」。

### A 端名单中的 B 端一直离线

- 检查 B 端 DSH 是否运行、B 端页面是否仍开启「作为 B 端」。
- 检查 B 端最后一个错误是否来自网络、地址或凭据撤销。
- A 端总开关关闭、B 端被撤销或网络中断时，任务会报「不在线」，不会自动落到 A 端本地执行。
- 恢复连接后，A 端名单应重新显示「在线」；若刚撤销过，需要在 A 端重新生成配对码并重新配对。

### 出现 HTTP 502 或远程窗口打不开

先检查 A 端的 Tailscale Serve 目标端口。默认手机服务端口是 `3090`，旧版本或旧配置可能仍指向 `3091`。

在 A 端终端执行：

```powershell
tailscale serve status
```

结果中的代理目标应类似：

```text
https://<机器名>.<tailnet>.ts.net
  -> http://127.0.0.1:3090
```

检查要点：

1. 代理目标必须是**当前手机服务实际监听的端口**，默认 `3090`；若仍为 `3091`，说明它指向旧服务。
2. 如果 `3090` 已被其他程序占用，插件会自动顺延端口。此时以「自检」显示的「在听端口」为准，不能盲目改成 `3090`。
3. 修改端口映射时，先确认手机服务已启动，再到 A 端「外部访问」将「HTTPS 地址（Tailscale）」关闭后重新开启，让插件按当前实际端口重新配置。
4. 也可由本机管理员执行 `tailscale serve --bg 3090`，再运行 `tailscale serve status` 复核；不要使用 `serve reset`，它会清除本机其他 Serve 配置。
5. 检查 A 端「允许别的电脑连接」是否开启、手机服务是否在监听，以及 B 端是否使用 `https://` 地址。

**恢复判据**：`tailscale serve status` 的代理目标指向当前手机服务端口；A 端「遥控设置」重新出现「Tailscale（加密）」地址；B 端重新点击远程窗口后可正常加载。

> 远程窗口内嵌的官方「新建工作区」按钮会在 A 端屏幕弹出系统目录对话框，B 端无法点击，可能以 `HTTP 502` 或超时结束。该入口应改用远程窗口顶部横条提供的「新建工作区」，由 B 端列出 A 端目录并登记。
>
> 若界面长期停在 `Loading plugins…`，可能是浏览器拦截了窗口所需的跨站凭据。可在浏览器中允许该站点的跨站 Cookie 后重试，或改用未启用严格拦截的浏览器。该凭据属于窗口会话，不等同于访问口令。

### 手机页面打不开或反复断开

- 局域网地址只在同一网络内有效；离开该网络后应切换到 Tailscale。
- 公网隧道首次开启需要下载组件并等待域名生效，约 30 秒；每次重启 DSH 后域名都会变化。
- Tailscale 地址不可达时，先检查两端是否登录同一 tailnet，再检查 A 端自检中的监听地址与防火墙。
- 页面被撤销授权后不会自行恢复，必须重新扫码。

### B 端文件任务被拒绝

| 报错或现象 | 先检查 | 恢复判据 |
| :--- | :--- | :--- |
| `b_read` 报「不在授权目录」 | B 端授权目录与传入路径是否同一个磁盘、同一层目录；路径中是否含 `..` | 改用授权目录内的绝对路径后读取成功 |
| `b_write` 报无权限 | B 端是否开启「允许 A 写这些文件夹」 | B 端状态重新在线后，写入测试文件成功 |
| `b_mkdir`、`b_copy`、`b_move`、`b_delete` 报无权限 | B 端是否开启文件夹管理 | 对应操作成功，且 B 端真实文件发生变化 |
| `b_shell` 报无权限 | 命令权限是独立开关，不会随写入权限一起开启 | 在明确风险后开启，`echo` 测试返回退出码 0 |

### 设置页没有 A/B 端协作或 B 项目

- 确认插件版本为 `0.2.5` 或更新版本，并重启 DSH。
- 旧进程可能仍在运行旧代码；以「自检」中的插件版本和进程启动时间为准。
- 配对成功但 B 项目入口不可用，先确认至少有一台 B 端在线且已有授权目录。

## 安全边界

以下边界不应为了简化文档而省略。

### 网络暴露

- 局域网和普通 Tailscale 地址使用明文 `http://`；同一网络中的其他设备可能观察到流量。Tailscale 的 HTTPS 地址提供加密连接。
- Cloudflare 公网隧道会把服务暴露到公网，流量经过 Cloudflare 中转；临时域名会变化，但域名变化不构成安全边界。
- 公网隧道地址和二维码含入场口令。口令泄露后，其他人可以登记设备并操作本机。不要在不可信网络或公开渠道使用和传播该地址。
- 飞书通道经过飞书开放平台，消息内容和可用范围受飞书应用权限与平台策略约束。
- 本插件不承诺公网部署安全。需要公网访问时，应自行评估网络环境、访问控制和主机安全。

### 凭据与设备

- 二维码和复制出的地址包含访问口令，应按密码保管；设置页本身也只允许在本机读取。
- 手机和电脑首次配对后各自持有设备凭据，可以在「设备」中单独撤销。撤销立即生效，但被撤销的设备必须重新扫码才能使用。
- 清除手机浏览器数据或更换手机后，原设备记录不会自动消失，需要时应在电脑上撤销。
- B 端 `machine-id` 只能复用同一数据目录下的身份。旧版无 `machine-id` 的记录、数据目录被删除后的记录，都可能成为无法自动合并的旧条目，需要手动撤销。
- 「清理 30 天未使用」只删除创建时间和最近使用时间都早于 30 天的记录；近期出现过的重复设备不会被清理，仍应手动核对。

### 插件与高权限界面

- 插件以当前用户权限运行。来源不明的插件可能损坏 DSH、读取文件或泄露凭据，只应安装可信来源的包。
- 手机端的「完全权限」允许 Agent 跨目录修改文件并执行系统命令；危险命令的审批卡只是最后一道人工确认，不能替代对任务本身的审查。
- 「进阶设置」中的电脑端界面会让手机获得完整 DSH 管理面，包括模型配置、凭据、插件装卸和会话记录。该开关默认关闭，开启需要二次确认。
- 远程窗口展示 A 端完整桌面界面，持有该窗口的 B 端可以看到并操作 A 端的管理面。只应向可信电脑开放「允许别的电脑连接」。

### A/B 端文件与命令

- B 端的授权目录、写入、文件夹管理和命令开关均由 B 端本地控制，A 端不能代为扩大。
- 命令权限的影响范围不限于授权目录，等于把整台 B 端电脑的命令执行能力交给 A 端 Agent，默认关闭。
- 删除、移动、复制等操作即使带模型层 `confirm`，也不是人工审批；真正的授权边界是 B 端开关和目录范围。
- B 项目只在 A 端建立门牌与路径映射，不复制文件。移除 B 项目不会删除 B 端文件，但会删除 A 端的门牌工作区。
- B 项目会话和文件面板只允许访问项目根目录内的路径；项目外路径必须另建项目。
- A 端的本地文件工具作用于 A 端，B 端文件只能通过 `b_*` 工具访问。混用会造成操作对象错误。

### 飞书

- 两个白名单都为空时，机器人不接受任何来源；应只加入可信的 `open_id`。
- 本版只处理单聊。把机器人拉入群聊可能让他人驱动本机会话，不应这样做。
- `App Secret` 具有密码性质，不应截图或转发；保存后界面不会再次回显。

## 开发与验证

本项目是运行在 DSH 中的 Node.js 插件。修改文档不需要重新构建客户端；修改代码或页面后，应重启 DSH 并重新验证。

### 本地检查

```bash
npm test
node client/verify.mjs
```

- `npm test`：运行 `test/*.test.mjs` 的离线测试，不要求 DSH 正在运行。
- `node client/verify.mjs`：验证 `client/client.js` 的模块注册、设置页组件、远程窗口和 B 项目面板。
- 发布前还可运行 `npm pack --dry-run`，检查实际打包内容和体积。

**0.2.5 发版验证记录**：

- `npm test`：**1190 通过，0 失败**
- `node client/verify.mjs`：**144 通过，0 失败**
- 在 DSH `0.2.1-rc.3` 上：兼容性检查 `COMPATIBLE`；宿主自检正常；B 端预设注册正常；测试使用该版本的 `dsh-tools`

这些数字是 0.2.5 发版时的记录。修改代码后应以当前环境的实际输出为准，不应把历史数字当作当前测试结果。
