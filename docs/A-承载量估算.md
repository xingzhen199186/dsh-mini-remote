# A 中继 Free 承载量估算

> 2026-10-27。估算，不是承诺；真实上限取决于用户每天请求量和 Cloudflare 当期额度。

## 改前：15 分钟心跳

每个常在线实例：

```text
96 次登记/天
每次登记写一次 KV target
KV Free：1,000 次写入/天
```

所以：

```text
1000 / 96 ≈ 10.4
```

安全线约 **8–10 个常在线实例**。

## 改后：不做周期心跳

- 只在 quick 地址启动/变化时登记；
- 固定地址 KV TTL 改为 90 天；
- 心跳不再每 15 分钟写 KV；
- 停止公网时仍显式注销。

KV 写入不再是主瓶颈。剩下：

| 资源 | Free 额度 | 估算 |
|---|---|---|
| Workers 请求 | 100,000/天 | 每个代理请求 1 次 |
| KV 读取 | 100,000/天 | 每个代理请求读 config + target = 2 次 |
| D1 读/写 | 5,000,000 / 100,000 行/天 | 很宽 |
| KV 写入 | 1,000/天 | 只在换 quick 地址时写 |

按每次代理 2 次 KV 读取：

```text
100,000 / 2 = 50,000 次代理请求/天
```

如果每个用户每天 1,000 次请求，理论上约 **50 人**；  
如果每个用户每天 5,000 次，约 **10 人**。

## 建议

- 首批 5–10 个；
- 观察运维台每日用量；
- Workers 到 50,000/天开始注意，80,000/天停止扩量；
- 要稳定超过 25 个活跃用户，评估 Workers Paid。
