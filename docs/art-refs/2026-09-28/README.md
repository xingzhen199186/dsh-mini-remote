# 立绘基准帧（2026-09-28 冻结）

这是「鲸鱼娘」九张立绘在 **2026-09-28** 定稿时的样子。用户当天在手机上确认"所有动画都 OK"，
并指定：**以后改动画，一律先跟这里的帧对照**，不要凭记忆重画。

## 里面有什么

- `frames/` —— 九张装好的雪碧图，和 **2026-09-28 当天** `lib/art/` 里跑的一模一样（每张 760×330，
  两帧并排，各 380×330，透明底）。这是**基准**：改动前后都要拿它比。
  2026-09-29 重出了「跑」和「冲刺」两张的头发（见文末），`lib/art/work-6-running.webp` 与
  `lib/art/work-8-sprinting.webp` 因此不再等于 `frames/` 里的同名文件——基准帧**故意不动**，
  留着当对照物。
- `prompts/` —— 出这批图用过的全部提示词原文，一次出图一对（`*-f1.txt` 画第一帧、
  `*-f2.txt` 由第一帧改出第二帧）。**每一轮重出都留着**，包括没被采用的中间版本，
  方便以后查"当时为什么把它换掉"。

## 改动画的规矩（用户 2026-09-28 指定）

1. **先对照。** 动手前把 `frames/` 里那一张调出来看，改完再并排比一遍。
2. **改动清单要写全。** 第二帧的提示词里必须列全这一帧该动的部位（冲刺＝腿＋鞋＋双臂＋头发），
   只把"其余不动"写进约束。写窄了会把它不该冻的一起冻住——这一轮为此返工过两次。
3. **量了再收。** 帧间差异占比、动的部位分段、腿的横向跨度，都用数字说话。
4. **好看见人。** 数字全过也要再看一眼成品图；用户对"太夸张、不协调、太开"很敏感。

## 2026-09-29：给「跑」补上摆动的头发（fix6 / fix7 / fix8）

**问题**：用户报「跑这个动作的立绘里，头发没有摆动」。查下来不是出图失败，是提示词写窄了——
`fix4-f2` 里那句 "keep the same hair and hair ornaments… only the legs, the shoes and the arm
swing change" 把头发一起冻住了，两帧头发逐像素相同（下表"基准"行的质心位移全在 2.3 像素内）。
这正是上面第 2 条那个坑的复现：跑该动的部位是腿＋鞋＋双臂＋**头发**。

**量头发的口径**：把头发按颜色权重（浅蓝、低饱和）分离出来，分四条横带（发根 25~70 行、
上段 70~120、中段 120~180、发梢 180~260）各量整幅宽度的加权质心位移（帧 2 减帧 1，正数=往右）。
"发根几乎不动、越往下位移越大"是甩出去；"发梢位移明显小于中段、甚至反号"是末端滞后。

| 版本 | 提示词 | 发根 / 上段 / 中段 / 发梢（像素） | 上身 / 腰腹 / 裙下 | 结论 |
| --- | --- | --- | --- | --- |
| 基准 fix4 | `fix4-f1/f2` | −0.5 / −0.6 / −0.5 / −2.3 | 20.1% / 59.0% / 40.6% | 头发逐像素没动 |
| fix6 | `fix6-f1` | — | — | 未采用：模型把人物整张重画了一遍（源图人物高 837 像素，基准 926，小了约 10%），

两版都过了下面的"没弄坏别的"检查（fix8 的数字）：踩地腿在 y=300 的中心 194 / 184（基准 190 / 184）、
换腿（y=235）踩地 200 / 184、抬起 172 / 211.5（基准 196 / 180.5、168 / 203.5），

差得最多的一处是抬起的那只鞋比基准远 8 像素（腿本身的张合没变：踩地到抬起的横向间距基准和
fix8 都是 28 像素）。fix8 的头发轮廓比基准宽（257 / 254 像素 vs 214），这是甩出去必然的结果，
也是这次唯一需要用户用眼睛定夺的地方。

**参照物**：当时的**冲刺**已经是一个"头发会摆动"的样子，同一套指标量出来是
发根 −8.5 / 上段 +50.1 / 中段 +7.5 / 发梢 **−35.7**——形状是对的（上面甩出去、发梢反号），
fix8 就是照这个形状做的，幅度约为它的 1.7 倍；fix7 不是（四项同向）。
（后来用户说冲刺"摆动的不够有动态不够真实"，即形状对、幅度小——所以冲刺那四个数当**形状**的
参照仍有效，当**幅度**的下限就不够了，见文末第二轮。）判断一个头发摆动"是不是整块被平移"，
拿它跟这四个数比形状，不要比大小。

**工具改动**：`tools/whale-pair.py` 增加 `--anchor-head`。原来的拼图法把"人物外框"居中，
而头发一甩到某侧，外框就跟着往那侧长，脸反被挤到另一边：两帧各甩一边时，同一张脸在两帧里
会横向挪开（fix7 没加这个开关时量到 73 像素，基准帧是 1 像素），播起来像整个角色在左右跳。
加了开关就改成把脸（外框上 45% 里肤色像素的中位 x）对到格子中线上；九张冻结基准帧量下来，
这个锚点两帧相差 0~1 像素（真前倾的冲刺是 22），fix7/fix8 加上后都是 1 像素。
默认行为不变，只有这个动作需要它。

## 2026-09-29（第二轮）：给「冲刺」把甩幅做上去（fix11 / fix12）

用户看过 fix8 的跑之后认可了，接着说冲刺："虽然头发会摆动，但是摆动的不够有动态不够真实"。
所以这一轮的目标不是"让头发动"（它本来就在动），而是**把幅度做上去、并保住"发梢反号"的形状**。
验收加了一条硬线：冲刺是更猛的动作，动态**不应弱于跑**。

把"甩幅"定义成上段与发梢这两个数的落差（一个往右、一个往左，落差越大越像在甩）：

| 版本 | 提示词 | 发根 / 上段 / 中段 / 发梢（像素） | 甩幅（上段−发梢） | 上身 / 腰腹 / 裙下 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 基准 fix10 | `fix10-f1/f2` | −8.5 / +50.1 / +7.5 / −35.7 | 85.8 | 62.4% / 68.9% / 100.0% | 要改的：形状对，幅度只有跑的一半 |
| 跑 fix8（已认可，当尺子） | `work-6-running-fix8-f1/f2` | +5.9 / +84.9 / +20.8 / −70.4 | 155.3 | 29.3% / 79.5% / 61.6% | 幅度基准线 |
| fix11 | `fix11-f1/f2` | +59.8 / +103.1 / +14.6 / **−80.5** | **183.6** | 41.4% / 70.4% / 72.2% | **装上这版**：上段比跑多走 18 像素、发梢比跑多反 10 像素(甩幅是跑的 1.18 倍、基准的 2.1 倍)，且形状与跑同一族 |
| fix12 | `fix12-f1/f2` | +70.5 / +120.8 / +89.4 / **+23.3** | — | 64.4% / 75.7% / 100.0% | 未采用：幅度最大，但**发梢不再反号**（四项同向），就是"整块被平移"那种读法 |

fix12 试的是另一个假设：让"贴头皮的那一段不动、只甩头发长度"（fix11 的发根走了 59.8 像素，
怀疑是整块平移）。结果相反——头发是整片一起走的，发梢也跟着走（+23.3），反号没了。
所以"发根走了多少"**不能**用来判这个动作是不是整块平移，见下面的口径说明。

fix11 过了"没弄坏别的"检查：踩地腿在 y=300 的中心 202 / 160（基准 203 / 167），
换腿（y=235）踩地 204.5 / 159.5、抬起 170.0 / 198.5（基准 205.5 / 164.5、171.5 / 197.0），
差得最多的一处 7 像素；两帧人物高 310、脚底 322、洋红残留 0、两帧动过 38.5% 的像素。
**脸的横向中心 193 / 171（基准 195 / 173），两帧之差 −22，与基准完全一致**——这 22 像素是
拼图时**特意保留**的，见下。

**口径说明一：冲刺那 22 像素不是"前倾"，但也不是缺陷，这里按"复现基准站位"处理。**
上面那段旧话把它写成"真前倾的冲刺是 22"。这一轮把它量清楚了：基准冲刺第 2 帧不止脸往左
22 像素，**裙子（不含头发的饱和蓝区域）质心也从 190.2 走到 175.4，即 15 像素**，腿也跟着走。
也就是说整幅画在两帧之间整体横移了 15~22 像素——和跑 fix7 那 73 像素是同一类拼接后果
（模型在画布里重新居中 + 拼图按外框居中），不是"头往前探"。前倾是这个姿势两帧都有的静态属性。
处理办法：`--anchor-head` 会把两帧的脸钉在同一处，等于把这个横移抹平；所以在拼图最后一步加了
`--dx2 −22`，把第 2 帧整体挪回基准帧的位置。这样"头发不再拖着人物漂"和"站位与基准帧一致"
两件事同时成立（脸 193/171 对 195/173，腿差 ≤7 像素）。

**口径说明二：发根那一带的位移，在头发又长又蓬的动作上不干净。** 那条带是成图第 25~70 行，
冲刺的头发蓬到把这一整段都占满，头发一甩，**被甩出去的那一大团本身就从这一带经过**，于是
"发根"的质心跟着走（fix11 走了 59.8）。跑那张在这一带只有贴头皮的一小撮，所以它的发根
稳定在 5.9。判断"是甩还是整块平移"要看**四条的分布形状**（发梢是否反号），不要只看发根。

**工具改动（这一轮）**：
- `tools/whale-pair.py`：按脸对齐后，两帧的头发各甩一边、落点又被钉在同一处，可能比一格还宽。
  原来的代码会**静默裁掉**出界的部分（fix11 的第一版就这么被削平了一条边，是 `whale-sprite.py`
  报出"离中缝 12px 内不透明像素 391"才发现的）。现在先算清楚：放不下就整体缩小（成图高度由
  whale-sprite 统一缩到 310，中间图缩小不影响成图尺寸），落点也从格中线挪到恰好容得下；
  仍然放不下就直接报错退出，不再写出被切过的图。
- `tools/whale-sprite.py`：增加 `--dx2 像素`，把第 2 帧整体横移。给"基准帧两帧站位本来就不同"
  的动作复现站位用（冲刺传 −22），默认 0＝两帧完全对齐。

## 2026-09-29（第三轮）：冲刺的头发改成程序化算出来的 6 帧（fix13，不花出图费）

用户看过 fix11 之后否了幅度这个方向：「甩得太夸张、幅度太大」，要的是「真实流畅的摆动，
实在不行就多做几帧」。前两轮都在调幅度那一个旋钮——旋钮治不了根：**一张两帧的雪碧图没有
"中间态"**，两帧之间只能硬切，再调大小也换不来流畅。这一轮换一条路：**把摆动从"画出来"
改成"算出来"**。

拿冻结基准帧当底，只给头发叠一条位移场，逐帧采样一个周期：

    横向位移 x(y,t) = 摆幅 × A(y) × sin(2π·k/N − φ(y)) × 渐隐(离身体的距离)

- `A(y)`：从发根 0 长到发梢 1（越末端摆得越大）——动画里的"跟随与重叠动作"（follow-through /
  overlapping action）：附属物总比主体晚一步，末端摆得最大。
- `φ(y)`：从 0 滞到 300°（越末端越晚）——就是"末端滞后"。游戏里用弹簧骨骼（spring bone，
  一条带阻尼的骨链）驱动头发是同一件事的物理版本，这里用的是它的几何版本。
- 渐隐：贴着身体的那几像素不动（否则头发一让开，身体与头发之间会裂出一道缝）。
- 长度补偿：横摆会把发丝"拉长"，按发长不变收回一点（摆幅 15 像素时不到 1 像素）。

**"身体逐像素不动"是构造出来的，不是调出来的**：判定为身体的像素直接从原图拷贝，
不经过重采样。脚本每跑一次自己数一遍，不一致的像素必须是 0（实测 **0**）。

指标仍用同一套四带口径（量第 1 帧与第 4 帧，即半周期后那一帧）：

| --- | --- | --- | --- | --- |
| 基准（两帧） | — | −8.5 / +50.1 / +7.5 / −35.7 | 85.8 | 用户说「不够有动态」 |
| fix11（两帧） | — | +59.8 / +103.1 / +14.6 / −80.5 | 183.6 | 用户说「太夸张」 |
| 算的 | 20 / 150° | −8.5 / +56.6 / +38.0 / −0.3 | 56.8 | 发梢不再反号：滞后不到 180° 时，整片头发同一瞬间朝同一个方向走 |

**为什么默认是"小摆幅＋大滞后"（15 / 300°）**：滞后小于 180° 时，整片头发在同一瞬间朝同一个
方向走（表里第一行，发梢只走到 −0.3，反号没了），读起来仍是"整块挪过去"——fix12 栽的是同一件事。
滞后一过 180°，"发根往右、发梢往左"才同时成立，四带呈"甩出去＋末端滞后"的形状。
关键推论：**同样的甩幅可以用"更小的摆幅＋更大的滞后"换到**，而摆幅正是形变的来源
（发梢那一带 71.6 像素的峰峰值，是靠相位滞后换来的，不是靠把摆幅拉大）。
所以默认选 15/300°，不选 40/260°。

**这一版消不掉的一件事（必须说清）**：两半的身体各用自己那一帧，换身体那一下（第 3 帧→第 4 帧）
头发的底稿也跟着换。把那两帧**自己画的**头发差异逐行量出来（每行质心差，扣掉两帧 22 像素的
站位差，正数＝第 2 帧相对脸更靠右）：

| 行带 | 第 2 帧相对第 1 帧（相对脸） |
| --- | --- |
| 25~70 | +0.2 ~ +42.8 |
| 70~120 | **+48.3 ~ +102.5** |
| 120~180 | +6.2 ~ +65.8 |
