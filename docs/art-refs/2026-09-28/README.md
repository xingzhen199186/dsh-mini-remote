这是「鲸鱼娘」九张立绘在 **2026-09-28** 定稿时的样子。用户当天在手机上确认"所有动画都 OK"，
并指定：**以后改动画，一律先跟这里的帧对照**，不要凭记忆重画。

## 里面有什么

- `frames/` —— 九张装好的雪碧图，和 **2026-09-28 当天** `lib/art/` 里跑的一模一样（每张 760×330，
  两帧并排，各 380×330，透明底）。这是**基准**：改动前后都要拿它比。
  2026-09-29 重出了「跑」那张的头发（见文末），`lib/art/work-6-running.webp` 因此不再等于
  `frames/work-6-running.webp`——基准帧**故意不动**，留着当对照物。
- `prompts/` —— 出这批图用过的全部提示词原文，一次出图一对（`*-f1.txt` 画第一帧、
  `*-f2.txt` 由第一帧改出第二帧）。**每一轮重出都留着**，包括没被采用的中间版本，
  方便以后查"当时为什么把它换掉"。

    python tools/whale-sprite.py  两格图 → 760×330 的 WebP（切图、抠洋红、两帧共用一个缩放）

## 改动画的规矩（用户 2026-09-28 指定）

1. **先对照。** 动手前把 `frames/` 里那一张调出来看，改完再并排比一遍。
2. **改动清单要写全。** 第二帧的提示词里必须列全这一帧该动的部位（冲刺＝腿＋鞋＋双臂＋头发），
   只把"其余不动"写进约束。写窄了会把它不该冻的一起冻住——这一轮为此返工过两次。
3. **量了再收。** 帧间差异占比、动的部位分段、腿的横向跨度，都用数字说话。
4. **好看见人。** 数字全过也要再看一眼成品图；用户对"太夸张、不协调、太开"很敏感。

## 2026-09-29：给「跑」补上摆动的头发（fix6 / fix7 / fix8）

**问题**：用户报「跑这个动作的立绘里，头发没有摆动」。查下来不是出图失败，是提示词写窄了——
`fix4-f2` 里那句 "keep the same hair and hair ornaments… only the legs, the shoes and the arm
swing change" 把头发一起冻住了，两帧头发逐像素相同（下表"基准"行的质心位移全在 2.3 像素内）。
这正是上面第 2 条那个坑的复现：跑该动的部位是腿＋鞋＋双臂＋**头发**。

**量头发的口径**：把头发按颜色权重（浅蓝、低饱和）分离出来，分四条横带（发根 25~70 行、
上段 70~120、中段 120~180、发梢 180~260）各量整幅宽度的加权质心位移（帧 2 减帧 1，正数=往右）。
"发根几乎不动、越往下位移越大"是甩出去；"发梢位移明显小于中段、甚至反号"是末端滞后。

| 版本 | 提示词 | 发根 / 上段 / 中段 / 发梢（像素） | 上身 / 腰腹 / 裙下 | 结论 |
| --- | --- | --- | --- | --- |
| 基准 fix4 | `fix4-f1/f2` | −0.5 / −0.6 / −0.5 / −2.3 | 20.1% / 59.0% / 40.6% | 头发逐像素没动 |
| fix6 | `fix6-f1` | — | — | 未采用：模型把人物整张重画了一遍（源图人物高 837 像素，基准 926，小了约 10%），
和冻结帧拼在一起会一张 310 像素一张 281 像素，身高对不上 |
| fix7 | `fix7-f1/f2` | +1.0 / +58.8 / +90.6 / +24.3 | 28.3% / 82.1% / 44.2% | 头发确实甩出去了，但四个带同向，发梢只比中段少走 66 像素，读起来仍偏"整块挪过去" |
| fix8 | `fix8-f1/f2` | +5.9 / +84.9 / +20.8 / **−70.4** | 29.3% / 79.5% / 61.6% | **装上这版**：上面往右走 85 像素、发梢反而往左走 70 像素，是"甩出去＋末端滞后" |

两版都过了下面的"没弄坏别的"检查（fix8 的数字）：踩地腿在 y=300 的中心 194 / 184（基准 190 / 184）、
换腿（y=235）踩地 200 / 184、抬起 172 / 211.5（基准 196 / 180.5、168 / 203.5），
两帧人物高都是 310、脚底都在 322、洋红残留 0、两帧动过 34.0% 的像素。
差得最多的一处是抬起的那只鞋比基准远 8 像素（腿本身的张合没变：踩地到抬起的横向间距基准和
fix8 都是 28 像素）。fix8 的头发轮廓比基准宽（257 / 254 像素 vs 214），这是甩出去必然的结果，
也是这次唯一需要用户用眼睛定夺的地方。

**工具改动**：`tools/whale-pair.py` 增加 `--anchor-head`。原来的拼图法把"人物外框"居中，
而头发一甩到某侧，外框就跟着往那侧长，脸反被挤到另一边：两帧各甩一边时，同一张脸在两帧里
会横向挪开（fix7 没加这个开关时量到 73 像素，基准帧是 1 像素），播起来像整个角色在左右跳。
加了开关就改成把脸（外框上 45% 里肤色像素的中位 x）对到格子中线上；九张冻结基准帧量下来，
这个锚点两帧相差 0~1 像素（真前倾的冲刺是 22），fix7/fix8 加上后都是 1 像素。
默认行为不变，只有这个动作需要它。
