# 自建多用户中继：安装包设计

> 定位：用户在自己的服务器、自己的域名上安装的多用户中继软件。
>
> 我们不提供服务器、不承载用户流量、不托管用户域名。
>
> 最后更新：2026-10-29

---

## 0. 一句话

```text
我们交付一套可安装的“多用户中继服务器软件”，
用户自己买 VPS、自己准备域名、自己运行。
```

不是把我们的腾讯云服务器开放给用户。

---

## 1. 和 A/B 的区别

| 项目 | A/B | 自建多用户中继 |
|---|---|---|
| 服务器 | 我们的 | 用户的 |
| 域名 | 我们的 | 用户的 |
| 流量 | 经过我们的设施 | 只经过用户自己的服务器 |
| 控制面 | 我们的 | 装在用户服务器上 |
| 管理后台 | 我们的运维台 | 用户自己的后台 |
| 我们负责 | 运营 | 提供安装包、升级、文档 |

---

## 2. 用户看到的样子

用户准备：

```text
一台 Ubuntu 22.04/24.04 VPS
一个域名，例如 example.com
把 relay.example.com 和 *.relay.example.com 指向 VPS
```

运行安装脚本：

```bash
sudo ./install.sh \
  --domain relay.example.com \
  --admin-host admin.relay.example.com \
  --email admin@example.com
```

安装完得到：

```text
管理后台：https://admin.relay.example.com
租户地址：<id>.relay.example.com
控制地址：frp-<id>.relay.example.com
```

管理员登录后：

```text
创建邀请码
→ 发给朋友
→ 朋友在插件里填邀请码
→ 自动开通一个固定地址
```

## 3. 服务器内部结构

```text
Nginx :443
  ├── admin.relay.example.com      → 控制面 127.0.0.1:8787
  ├── frp-<id>.relay.example.com   → frps 127.0.0.1:7100+N
  └── <id>.relay.example.com       → frps vhost 127.0.0.1:8100+N

控制面（普通用户运行）
  ├── SQLite
  ├── 管理后台
  ├── 邀请码 / 租户 / 审计
  └── 调 root helper 建/删 frps 和 Nginx 配置

frps 实例（每个租户一个）
  ├── /etc/relay-multi/tenants/<id>.toml
  ├── systemd: frps@<id>.service
  ├── bind 127.0.0.1:7100+N
  ├── vhost 127.0.0.1:8100+N
  └── 独立 token
```

---

## 4. 每个租户的资源

```text
id：26 位小写 base32
数据地址：<id>.relay.example.com
控制地址：frp-<id>.relay.example.com
frps 控制端口：7100 + N
frps vhost 端口：8100 + N
独立 frp token
独立 systemd 服务
独立 Nginx server block
```

端口范围建议：

```text
7100–7199 控制
8100–8199 vhost
最多 100 个租户
```

第一版默认上限：

```text
20 个租户
```

## 5. 控制面

### 5.1 技术选型（建议）

```text
Python 3 + FastAPI + SQLite
systemd 托管
普通用户 relay 运行
```

理由：

- Ubuntu 自带 Python；
- 依赖少；
- 管理后台和 API 可以放一个进程；
- SQLite 对 20 个租户足够。

如果以后要单二进制，再考虑 Go 重写。

### 5.2 数据表

```text
admins          管理员、密码哈希
invites         邀请码哈希、过期、使用状态
tenants         租户、子域名、端口、token_hash、状态、时间
ops_runs        开通/删除/对账运行记录
audit           管理操作审计
config          注册开关、邀请码开关、最大租户数
```

不存明文 token、不存明文邀请码。

### 5.3 API

管理端：

```text
POST /admin/api/login
GET  /admin/api/overview
GET  /admin/api/tenants
POST /admin/api/invites
POST /admin/api/tenants/<id>/revoke
POST /admin/api/tenants/<id>/retire
GET  /admin/api/audit
POST /admin/api/config
```

插件端：

```text
POST /api/claim
POST /api/status
POST /api/renew
POST /api/release
```

claim 返回：

```json
{
  "id": "...",
  "publicHost": "<id>.relay.example.com",
  "controlHost": "frp-<id>.relay.example.com",
  "frpToken": "...",
  "frpsPort": 443,
  "transport": "wss"
}
```

`frpToken` 只在开通时返回一次；服务端只存哈希。

## 6. root helper

控制面不能以 root 跑网页。

需要一个 root helper：

```text
/usr/local/lib/relay-multi/helper
```

只接受固定动作：

```text
create-tenant <id> <control-port> <vhost-port>
delete-tenant <id>
reload-nginx
```

helper 自己校验：

- id 格式；
- 端口在允许范围；
- 不覆盖已有配置；
- 只写 `/etc/relay-multi/` 和 `/etc/nginx/conf.d/zz-relay-*`；
- `nginx -t` 通过才 reload。

sudoers 只允许 `relay` 用户执行这个 helper。

## 7. Nginx 模板

### 7.1 控制块

```nginx
server {
  listen 443 ssl;
  server_name frp-<id>.relay.example.com;

  ssl_certificate ...;
  ssl_certificate_key ...;

  location / {
    proxy_pass http://127.0.0.1:<control-port>;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $relay_ws_upgrade;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
  }
}
```

### 7.2 数据块

```nginx
server {
  listen 443 ssl;
  server_name <id>.relay.example.com;

  ssl_certificate ...;
  ssl_certificate_key ...;

  location / {
    proxy_pass http://127.0.0.1:<vhost-port>;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $relay_ws_upgrade;
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_read_timeout 3600s;
    client_max_body_size 50m;
  }
}
```

所有动态配置用：

```text
/etc/nginx/conf.d/zz-relay-<id>.conf
```

文件名必须 `zz-` 前缀，避免抢默认站点。

## 8. 证书

### 第一版：每租户单独签

用 HTTP-01：

```text
<id>.relay.example.com
frp-<id>.relay.example.com
```

优点：

- 不需要 DNS API；
- 用户不需要配 DNS 凭据。

缺点：

- 每个租户两张证书；
- 证书数量多；
- Let's Encrypt 有速率限制。

### 第二版：泛域名

```text
*.relay.example.com
```

用 DNS-01，需要用户的 DNS API。

支持：

```text
Cloudflare
DNSPod
手动 DNS
```

第一版先支持 HTTP-01，跑通后再加泛域名。

## 9. 安装脚本

### 9.1 参数

```bash
sudo ./install.sh \
  --domain relay.example.com \
  --admin-host admin.relay.example.com \
  --email admin@example.com \
  --max-tenants 20
```

可选：

```text
--tls http01|wildcard
--dns cloudflare|dnspod|manual
--no-nginx-reload
```

### 9.2 流程

```text
1. 检查 root / Ubuntu / 端口 / Nginx / certbot
2. 检查 relay.example.com 是否解析到本机
3. 创建 relay 用户和目录
4. 安装控制面依赖
5. 生成管理员密码和数据库
6. 安装 root helper 和 sudoers
7. 配置基础 Nginx / 证书
8. 启动 relay-control
9. 输出管理后台地址和初始密码
10. 跑一次自检
```

### 9.3 自检

```text
控制面 /health
管理后台可打开
SQLite 可写
Nginx 配置检查通过
frps 模板可启动
```

## 10. 管理后台

第一版：

```text
总览：租户数、在线数、邀请数、容量
租户：地址、状态、端口、最近在线、撤销/退休
邀请：创建、复制、过期
配置：允许注册、必须邀请码、最大租户数
审计：最近操作
```

登录：

```text
Basic Auth
+ 强密码
+ 可选 IP 白名单
```

后续可加 Cloudflare Access。

## 11. 插件端

新增一条“邀请码开通”模式：

```text
填服务器地址 + 邀请码
→ 调 /api/claim
→ 拿到 publicHost / controlHost / token
→ 写 frpc 配置
→ 启动 frpc
→ 固定地址进二维码
```

保留现有“手动填服务器/域名/token”的高级模式。

## 12. 安全边界

- 每个租户独立 frps、独立 token；
- frps 只 bind 127.0.0.1；
- 公网只开 Nginx 443/80；
- 控制面不以 root 运行；
- root helper 只接受固定动作；
- 邀请码和 token 只存哈希；
- 管理后台不暴露 token；
- 所有开通/撤销/删除写审计；
- 默认必须邀请码；
- 自服务开关默认关；
- 每 IP / 全局限流；
- 最大租户数可配。

---

## 13. 容量

每个 frps 很轻，但控制面、Nginx、SQLite、证书也要占资源。

建议：

```text
2 GB 内存：10–20 个租户
4 GB 内存：30–50 个租户
```

安装时按 `--max-tenants` 限制，不要等打满。

---

## 14. 升级和卸载

```bash
sudo ./upgrade.sh
sudo ./uninstall.sh
```

升级：

- 备份 SQLite；
- 替换控制面代码；
- 跑 migration；
- 重启 relay-control；
- 不动租户 frps。

卸载：

- 停 relay-control；
- 停所有 frps@；
- 删除 Nginx 配置；
- 保留数据目录，除非 `--purge`。
