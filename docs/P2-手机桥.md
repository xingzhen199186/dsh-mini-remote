# P2 手机桥：电脑 → 手机（2026-11-09 落地）

手机上的 App 打开「手机桥」之后，电脑上的 AI 可以**把东西送到手机上**。只有四个动作，别的都不碰。

## 四个工具与边界

| 工具 | 做什么 | 用户要做什么 | 上限 |
|---|---|---|---|
| `phone_notify` | 发通知，带链接时点开就打开 | 看一眼 / 点一下 | 标题 80 字、正文 300 字 |
| `phone_status` | 电量、充电、屏幕、锁屏、网络 | 不用管（只读） | — |
| `phone_send_file` | 文本存到「下载/DSH」并发通知 | 点通知打开 | 20 万字符，**只发文本** |
| `phone_set_clipboard` | 写剪贴板 | **每次都要点通知上的按钮** | 4000 字符，等待 120 秒 |

**明确不做**：读剪贴板、读短信、读通知、读相册。要手机上的数据，只能由用户自己用系统分享发过来。

## 协议（够用就好，不追求完整）

- 手机**长轮询** `GET /mini/api/bridge/poll?wait=1&protocol=1`，服务端最多压 25 秒；第一拍用 `wait=0` 立刻回，避免用户盯着「正在连接」干等。
- 电脑有话说时**立刻唤醒**那个挂着的轮询，不用等下一轮。
- 武装状态由手机通过 `POST /mini/api/bridge/arm` 写入；**电脑没有别的入口**，不能替用户打开。
- 结果由手机 `POST /mini/api/bridge/result` 回报。
- **不重投**：取走即清空。重复弹通知 / 重复写文件比失败一次更糟。
- 「在线」= 90 秒内来问过，不是"连过就一直算"。

## 保活

- 心跳平时住在界面里；**退到后台时交给前台服务**继续跑，界面被回收也不断。
- 断网退避：5s → 10 → 20 → 40 → 60 封顶，成功一次归零。
- **未覆盖**：App 被系统杀掉 / 手动上划清掉之后不会自己回来。解决它要碰省电白名单，代价是更耗电，留作单独决策。

## 与 RFC 的偏差（如实记下）

RFC 6.4 要求"没武装时模型连工具都看不到"。当前实现是**常驻注册、执行时拒绝**：不武装时模型仍会看到一行工具说明。做成真·隐身要按武装状态动态改工具清单，尚未做。判断依据是"看得到但用不了"不会导致错误动作。

## 验收记录（真机，2026-11-09）

| 项 | 证据 |
|---|---|
| 通知 | 手机弹出，标题用的是电脑给的那句 |
| 状态 | 读出 64% → 58%（数值会变，不是缓存） |
| 送文件 | 「下载/DSH」里有文件，51 字节，内容逐字一致 |
| 剪贴板 | 先弹确认，用户点了才写，随后回报「已复制」 |
| 后台 | App 退到桌面后仍能答上状态查询 |

## 这一天踩过的六个坑

1. **通知标题被写死**：工具报告成功，用户看到的却是「DSH 任务完成」。报告成功 ≠ 用户看到对。
2. **漏声明权限**：读网络要 `ACCESS_NETWORK_STATE`，缺了会抛异常，还会把同一段里的电量一起带走。修法是**每项单独兜住**，一项失败不影响其他。
3. **状态对、界面不刷新**：上线那一刻的推送落空，之后状态不再变化就不再推。补一条每 3 秒自读。
4. **武装请求没发出去**：只在本地存了开关，电脑那边永远"没武装"，心跳于是自我劝退。
5. **页面就绪后才该启动心跳**：注入那一刻还没有地址，那一次直接跳过，之后没有第二次机会。
6. **长轮询第一拍等 25 秒**：用户以为坏了。第一拍改成短请求。

## 开发期开关：屏幕拦截已关闭（2026-11-09）

`BridgeAccessibilityService.ALLOW_ALL_SCREENS = true`（提交 e229042）。

- 该开关是观察、截图、点击**三处共用的闸门**，一处放开即全部放开；
- 现在**不拦**锁屏、银行/支付/钱包页、短信验证码、密码框整屏；
- 恢复保护：把常量改回 `false`，重新打包安装（无需重新排查）；
- **发布前必须关闭**。用户已明确知道这一点，并选择暂不加“发布版强制关闭”的保险——
  这是知情后的决定，不是遗漏；
- 相关实证：测试时曾误点一次微博点赞，当场撤回。**能点 ≠ 点得准**，这条留作提醒。

## 已知毛病：重启电脑后手机不会自己回来（2026-11-10）

现象：电脑端重启 DSH 后，手机桥一直是「未连接 / 离线」，任何工具都回
「手机桥没打开或不在线」，直到**用户在手机上把「手机桥」关掉再打开**一次。

原因（已定位）：武装状态与电脑地址存在手机侧，重启后电脑端是全新进程，
旧地址/旧武装不再有效；手机的心跳不会主动重新登记，只会在失败里退避。

为什么会静默：界面上的开关仍显示为“开”，用户看到的是“已经打开了”，
但桥其实没连上。**表现是功能失效，不是报错。**

修法方向（未实施）：
1. 心跳失败若干次后，自动重新读一次电脑地址并重新武装（不依赖用户拨开关）；
2. 设置页那一行在“开关开着但连不上”时给出**明确一句话**，而不是留着“已连接”字样；
3. 或者电脑重启后主动广播一次“我换了地址”，让手机收到就重连。

今天在真机上重复出现 3 次，成本是每次都要人手动拨一下。
