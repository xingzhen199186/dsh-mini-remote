# 固定地址运维手册

> 适用：dsh-mini-remote 的「共享固定地址」与「专属固定地址」两条公网路径。
>
> 状态：2026-10-28 第一版。A 已上线；B 控制面、插件、运维台已跑通，自动清理和对账尚未完成。
>
> 原则：先保数据面，再修控制面，最后清理资源。任何删除、撤销、轮换都要留下记录。

---

## 0. 快速信息

### 用户看到的两个名字

| 名字 | 内部叫法 | 固定地址 | 数据怎么走 |
|---|---|---|---|
| 共享固定地址 | A | `<id>.dsh-mini-remote.com` | 手机 → Cloudflare → 公共中转 Worker → 快速隧道 → 用户电脑 |
| 专属固定地址 | B | `<id>.dsh-everywhere.com` | 手机 → Cloudflare → 用户专属命名隧道 → 用户电脑 |

两条都不是端到端加密：

- 共享固定地址：我们的 Worker 和 Cloudflare 都可能看到明文；
- 专属固定地址：我们的 Worker 退出业务路径，但 Cloudflare 仍在中间。

### 运维入口

```text
运维台：https://relay.dsh-mini-remote.com/admin
共享控制面：https://relay.dsh-mini-remote.com
专属控制面：https://control.dsh-everywhere.com
只读快照：https://relay.dsh-mini-remote.com/ops/v1/snapshot（Bearer OPS_READ_TOKEN）
```

专属控制面目前只有 API，没有独立页面；日常查看统一走运维台的「专属固定地址」页。

### 本机密钥位置

```text
A 控制面 token / 部署凭据：按现有 wrangler 配置
B Cloudflare API token：C:\Users\WINDOWS\.dsh\dsh-mini-remote-b\cf-api-token.txt
B 管理 token / pepper：C:\Users\WINDOWS\.dsh\dsh-mini-remote-b\b-secrets.json
```

这些文件不进仓库、不进聊天、不进日志。换机器时单独加密迁移。

## 1. 两条路的运维重点

### 共享固定地址

重点是一个公共中转站：

- Worker 是否正常；
- D1 / KV 是否正常；
- 每日请求量是否接近 Free 上限；
- 邀请码和撤销是否干净；
- 数据面开关是否被误关。

它的问题会同时影响一批用户，所以看的是“整体水位”。

### 专属固定地址

重点是 Cloudflare 账户里的资源：

- 每条租约对应一条 Tunnel、一条 CNAME、一份 ingress；
- 隧道是否还在、CNAME 是否指对；
- released 是否到期、retired 是否真的清干净；
- 账户 Tunnel 总数是否接近配额；
- API token 和 admin token 是否安全。

它通常只影响一个用户，但资源关系更复杂，最怕孤儿和漂移。

## 2. 角色和权限

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 人工运维 | 看板、发邀请、撤销、释放、退休、轮换、回滚 | 不在未确认归属时覆盖未知 DNS |
| AI 助手（第一版） | 读看板、做日报、发现异常、起草回复 | 不自动删除 Tunnel/CNAME、不自动撤销用户、不自动轮换密钥 |
| Cloudflare Access | 保护 `/admin` 页面 | 不是用户身份系统，不能代替租约鉴权 |

AI 接入的边界见第 12 节。

## 3. 每天做什么

每天打开运维台，按下面顺序看一遍。正常情况 5～10 分钟。

### 3.1 总览

看两组数字：

```text
共享固定地址：活跃实例 / 已撤销 / 未用邀请 / 数据面
专属固定地址：租约总数 / 已连接 / 已释放 / 已退休
```

异常信号：

- 活跃实例突然掉很多；
- 已撤销突然涨很多；
- 未用邀请长期堆积；
- 数据面变成“停用”；
- 专属租约总数只涨不降；
- 已释放长期不退休。

### 3.2 共享固定地址页

- 今日用量：Workers 请求、D1 读写、KV 请求；
- 是否接近 Free 上限；
- 最近审计有没有陌生操作；
- 实例列表有没有该撤销的；
- 邀请列表有没有过期未用的。

### 3.3 专属固定地址页

- active 租约的“最近登记”是不是很久以前；
- released 租约的释放时间；
- retired 租约对应的 Cloudflare 资源是否真的没了；
- 新激活码有没有发出去；
- 隧道总数是否接近 700 / 800 / 900 的规划线；
- “最近对账”是否成功，有没有 finding。

### 3.4 外部状态

- Cloudflare 控制台有没有账户通知；
- Worker 有没有报错；
- 用户有没有集中反馈“打不开”；
- 国内自建中继 `remote.tzxwdscb.icu` 是否还正常。

## 4. 每周做什么

### 4.1 共享固定地址

- 统计本周新增、撤销、活跃；
- 看用量曲线，判断是否要提前迁用户到专属；
- 清理过期邀请；
- 抽查 1～2 个用户的固定地址是否能打开；
- 看审计里有没有重复失败的操作。

### 4.2 专属固定地址

- 对账：D1 租约 vs Cloudflare Tunnel / CNAME；
- 找出 released 超过 30 天的租约；
- 找出 active 但长期没有登记的租约；
- 找出 D1 没有、Cloudflare 有的孤儿；
- 找出 CNAME 指向别的 Tunnel 的漂移；
- 清理过期未用的激活码；
- 抽查 1～2 条固定地址的 `/mini/api/version`。

### 4.3 容量线

| 项目 | 观察线 | 处理 |
|---|---|---|
| A Workers 请求 | 每天 6 万～7 万 | 停止新注册，准备迁移 |
| A KV 读取 | 每天 6 万～7 万 | 同上 |
| B Tunnel 总数 | 700 | 开始清理 released / 孤儿 |
| B Tunnel 总数 | 800 | 暂停新开通，人工审核 |
| B Tunnel 总数 | 900 | 只允许退休，不再新增 |

## 5. 每月做什么

- 备份 A 和 B 的 D1；
- 备份 Worker 配置、本机密钥（加密）；
- 检查 Cloudflare Access 白名单；
- 检查 B 的 Cloudflare API token 权限；
- 轮换 B 管理 token；
- 检查 Tunnel 配额和账户通知；
- 做一次真实验收（见第 11 节）；
- 看插件和 Worker 的版本，确认可回滚；
- 复盘本月事故和用户反馈。

### 备份命令

```powershell
# A
npx wrangler d1 export dsh-mini-relay --remote --output backup\a-YYYYMMDD.sql -c worker\wrangler.jsonc

# B
npx wrangler d1 export dsh-b-relay --remote --output backup\b-YYYYMMDD.sql -c worker-b\wrangler.jsonc
```

备份文件不要提交到仓库。密钥单独加密存放。

## 6. 用户生命周期

### 6.1 共享固定地址

```text
发邀请码
→ 用户首次注册
→ active
→ 不用了：运维台撤销
→ 固定地址立即失效
```

注意：

- 撤销是立即生效；
- 撤销后同 secret 也不能恢复；
- 邀请码只给一次，不要公开贴。

### 6.2 专属固定地址

```text
运维台新建 7 天激活码
→ 用户插件填码
→ claim 成功，state=active
→ 用户停止：release，资源保留 30 天
→ 30 天后：retire，删 CNAME、删 Tunnel、留墓碑
```

注意：

- 激活码只显示一次；
- 停止不是安全阻断，只是释放租约；
- 真正的删除是退休；
- 用户 clientSecret 只在本机，丢了不能从服务端找回；
- 丢 secret 的用户，按“退休后重新发码”处理，不要直接改数据库。

### 6.3 用户离场

共享：

```text
撤销 → 确认固定地址失效 → 记录原因
```

专属：

```text
先停 cloudflared
→ release
→ 到期后 retire
→ 确认 CNAME / Tunnel 都不存在
→ 记录墓碑
```

## 7. 自动退休与对账

B 控制面每天北京时间 09:20 跑一次 `runOps`：

- 自动退休 `released` 超过 30 天的租约，每次最多 10 条；
- 单条失败不影响同批其它租约，下一轮继续；
- 对账 active/released 的 Tunnel 和 CNAME；
- 发现 `dsh-b-relay-` 前缀的孤儿 Tunnel 只记录，不删除；
- 每次写一条 `b_ops_runs`，finding 写到 `b_reconcile_findings`。

运维台「专属固定地址」页有“立即对账”按钮，会手动跑同一套逻辑。  
“立即对账”会顺带尝试退休 released 超过 30 天的租约，所以按钮有二次确认。

对账目前只覆盖 Tunnel 和 CNAME，不核对 ingress；`listTunnels` 只取第一页 100 条，分页外的孤儿暂不可见。

## 8. 事故处理

### 7.1 共享 Worker 挂了或大面积 5xx

先查：

- Cloudflare 最新部署版本；
- D1 / KV 是否正常；
- Access 是否误挡；
- 数据面开关是否被关。

处理：

- 能回滚就回滚；
- 不能马上恢复，通知用户临时切快速隧道、自建中继或专属固定地址；
- 不要在故障中做无关变更。

### 7.2 共享配额快满

顺序：

1. 关闭新注册；
2. 暂停发邀请；
3. 把活跃用户迁到专属；
4. 不靠删老用户硬撑。

### 7.3 专属控制面挂了

已连上的用户通常不受影响。  
受影响的是新 claim、release、retire 和看板。

处理：

- 恢复 Worker / D1；
- 不要因为控制面挂了就删 Cloudflare 资源；
- 恢复后先对账，再操作。

### 7.4 某个专属隧道断了

先查：

- 用户电脑上的 cloudflared 是否在跑；
- 插件是否在退避重连；
- Tunnel 是否被删；
- CNAME 是否还在。

处理：

- 进程没起来，让用户重新开启；
- Tunnel 被误删，按租约记录重建；
- CNAME 指错，先标记异常，确认归属后再改；
- 不要看到同名记录就覆盖。

### 7.5 退休删不掉

常见原因：Tunnel 还有活动连接。

处理：

- 停 cloudflared；
- 等连接关闭；
- 再重试退休；
- 不要一上来强制删。

### 7.6 密钥泄漏

- 立即吊销 Cloudflare API token；
- 重新建最小权限 token；
- 轮换 B 管理 token；
- 检查审计和 Cloudflare 操作记录；
- `B_PEPPER` 只在确认泄漏时换；换了以后所有 clientSecret 哈希失效，用户需要重新认领，影响面很大。

## 9. 容量与迁移

### 共享固定地址

当前估算：

```text
Worker Free：10 万请求/天
KV Free：10 万读取/天
去掉 15 分钟心跳后，约 2 次 KV 读取/请求
实际约 5 万代理请求/天
视使用强度，约 10～50 个活跃用户
```

超过观察线就迁专属，不要等打满。

### 专属固定地址

```text
Cloudflare Tunnel 规划基线：1000 条/账户
每条租约：1 条 Tunnel + 1 条 CNAME + 1 份 ingress
```

容量计数要算：

```text
active + released 保留 + 孤儿 + 测试资源
```

不是只看 active。

## 10. 安全底线

- 管理页必须在 Cloudflare Access 后面；
- B 的 Cloudflare API token 只给 Tunnel Edit + 指定 zone 的 DNS Edit；
- B 的 admin token 是高权限密钥，当前放在 A Worker 里做只读汇总，要按高权限管理；
- token 不进浏览器、不进二维码、不进日志、不进仓库；
- 未知 DNS 记录永不自动覆盖；
- 删除操作必须有归属证据；
- 所有管理写操作要有审计；
- 两条路都不是端到端加密，敏感内容不要走公网。

## 12. 可视化与自动采集

运维台左侧新增「可视化」页，展示：

- 系统健康：共享数据面、专属控制面、专属连接率、采集时间；
- 容量水位：Workers、KV、D1 读写、专属 Tunnel 数量；
- 专属租约分布：已连接、已释放、已退休；
- 最近趋势：最近 30 次采集的共享请求和专属租约；
- 异常：用量接近线、released 超过 30 天、active 长期不登记、控制面读不到等。

采集分两条：

```text
Cloudflare Cron（每天 10:00）：刷新用量 + 写 ops 快照和历史
运维台「可视化」页「立即采集」：手动刷新用量 + 写快照
```

快照存在 A 的 KV：

```text
ops:snapshot:latest
ops:snapshot:history
```

只读 AI 用 `GET /ops/v1/snapshot`，需要 `OPS_READ_TOKEN`。这个端点不在 `/admin` 的 Access 后面，只靠 token 保护；token 只给只读日报使用。

### 只读日报脚本

```powershell
node scripts/ops-report.mjs
```

它只读快照，输出 Markdown 日报，不写任何资源。

### DSH 定时任务

当前已建两个：

```text
每天 09:00（Asia/Shanghai）生成固定地址运维日报
每周一 09:10（Asia/Shanghai）生成固定地址每周运维清单
```

日报脚本：

```powershell
node scripts/ops-report.mjs
```

周报脚本：

```powershell
node scripts/ops-weekly.mjs
```

周报会列：

- 共享固定地址长期不活跃的实例；
- 共享固定地址超过 7 天未使用的邀请；
- 专属固定地址 released 超过 30 天的租约；
- 专属固定地址 active 但超过 7 天没有登记的租约；
- 容量水位。

两个脚本都只读，不改任何资源。

注意：DSH 必须开着才会跑。  
如果电脑关了，Cloudflare 的 10:00 采集仍会跑，但 09:00/09:10 的 AI 日报和周报不会。

## 14. AI 能不能接入运维

可以，但要分阶段。  
AI 最适合做“看、算、写报告、提醒”，不适合一上来就“自动删资源”。

### 第一阶段：只读日报

AI 每天读：

```text
/admin/relay/v1/overview
/admin/relay/v1/identities
/admin/relay/v1/audit
/admin/relay/v1/usage
/admin/relay/v1/b/leases
```

产出：

- 今天新增/撤销/释放/退休；
- 用量和容量线；
- 异常租约；
- 需要人工处理的清单。

这一阶段只读，零风险，建议先做。

### 第二阶段：AI 起草，人确认

AI 可以：

- 起草给用户的回复；
- 起草邀请/激活码发放说明；
- 生成每周运维报告；
- 给出“建议退休/建议撤销”的名单。

人确认后再执行。

### 第三阶段：有边界的自动动作

只对低风险、可证明的动作开放，例如：

- 把 released 超过 30 天的租约标成“待退休”；
- 把长期不活跃的 A 实例标成“待撤销”；
- 创建邀请码草稿；
- 发送提醒。

仍然不自动删除 Tunnel / CNAME。

### 第四阶段：审批式执行

如果确实要让 AI 执行删除类动作，必须满足：

- 有明确的资源归属证据；
- 先 dry-run，列出将删除什么；
- 人工在页面上二次确认；
- 操作幂等、可重试；
- 全程审计；
- 有 kill switch；
- 不碰未知 DNS、不碰其他租户资源。

### 推荐架构

```text
AI 只读 token → 读 API → 生成日报/建议
人工确认 → 受控动作接口 → 审计
```

不要让 AI 直接拿 Cloudflare 账户级 token。  
不要让 AI 直接改 D1。  
不要让 AI 在聊天里看到 token。

### 现在就能做的

- 每天 09:00 DSH 只读日报（已建）；
- Cloudflare 每天 10:00 采集快照（已接）；
- 每周一 09:10 生成“待退休 / 待撤销 / 未使用邀请”清单（已建）；
- 把日报发到飞书或本机（飞书先不做）；
- 人按清单执行。
