# 公网隧道

适合：出门也要用，不想装 Tailscale，只是临时用一下；如果你已经在外面配好了公网入口，也可以直接看下面的「手动公网地址」。

1. 打开「设置 → 遥控设置 → 连接与固定地址 → 公网访问」。
2. 打开公网访问开关。
3. 第一次会下载一个约 50 MB 的组件，等它完成。
4. 等设置页出现「公网」地址后，用手机扫码。

## 临时地址做完应该看到

- 设置页出现一条 `https://...` 的公网地址；
- 手机用流量也能打开。

## 临时地址注意

- 每次重启 DSH，这个临时地址都会变；
- 它不是固定地址，不适合长期收藏；
- 想要固定网址，用共享固定地址、专属固定地址或自建中继。

## 连不上先查

- 等 30 秒，首次域名生效需要时间；
- 看设置页有没有报错；
- 公司网络或校园网可能拦截，换手机流量再试。

## 固定地址（Cloudflare 命名隧道）

如果不想每次重启都换地址，可以用 Cloudflare 的命名隧道。需要：一个接入 Cloudflare 的域名、一个 Cloudflare 账号。

1. 打开 Cloudflare Zero Trust，进入 Networks → Tunnels → Create a tunnel，选 Cloudflared。
2. 保存后复制安装命令里的 `--token` 后面那一串，只复制 token。
3. 在隧道详情里添加 Public Hostname：
   - 子域：例如 `dsh`
   - 域名：你的域名
   - 服务：HTTP
   - URL：`http://127.0.0.1:3090`（端口以自检显示的实际端口为准）
4. 回到「设置 → 遥控设置 → 连接与固定地址 → 公网访问 → 固定地址」。
5. 公网地址填 `https://dsh.example.com`，隧道 token 粘贴进去。
6. 点「保存并开启」，状态变成「已连接」后扫码。

## 固定地址做完应该看到

- 设置页出现固定公网地址；
- DSH 重启后地址不变；
- 手机用流量能打开。

## 固定地址注意

- token 是密码，不要截图或发人；
- 404 多半是公网地址和 Public Hostname 不一致；
- 502 多半是本机端口没开或填错；
- 这条经过 Cloudflare，不是端到端加密。

## 手动公网地址（Tailscale Funnel / 反向代理）

如果你已经在插件外面配好了 [Tailscale Funnel](https://tailscale.com/kb/1223/funnel)、反向代理或其他公网入口，只想让插件显示这个地址并生成二维码，可以用这一项。

先说清分工：公网入口由你自己建立和维护，插件只负责显示地址和生成二维码，不建立、不探测、也不修复链路。

### 以 Tailscale Funnel 为例

普通的 Tailscale 连接只允许同一 tailnet 里的设备访问，Funnel 才会把指定端口开放到公网。

下面以公网端口 `10000`、本机手机服务端口 `3090` 为例，机器名、tailnet 名和端口要换成你自己的。

#### 1. 准备 Tailscale

1. 在电脑和手机上都安装 Tailscale，并登录同一个 tailnet。
2. 打开 Tailscale 管理后台的 DNS 页面，确认 MagicDNS 和 HTTPS Certificates 都已开启。
3. 打开 Access controls，确认 tailnet 策略的 `nodeAttrs` 已允许目标设备使用 `funnel` 节点属性；如果没有，先在现有策略中添加并保存，不要覆盖其他策略。
4. 回到插件，打开「设置 → 遥控设置 → 诊断与高级 → 自检」，查看本机手机服务的实际在听端口。

做完应该看到：电脑和手机都已加入同一个 tailnet，MagicDNS、HTTPS 和 `funnel` 节点属性已就绪，你也记下了自检显示的实际端口。

常见端口是 `3090`；如果自检显示的不是 `3090`，下面的命令就要换成实际端口。

#### 2. 在电脑上开 Funnel

1. 在电脑上打开 PowerShell 或终端。
2. 执行：

   ```powershell
   tailscale funnel --bg --https=10000 3090
   ```

3. 如果自检显示的实际端口不是 `3090`，把命令最后的 `3090` 换掉，`10000` 仍然表示公网 HTTPS 端口。

做完应该看到：命令输出一条类似 `https://<机器名>.<tailnet>.ts.net:10000/` 的地址。

这里的两个端口方向不同：

- 命令最后的 `3090` 是插件在这台电脑上的手机服务端口；
- `--https=10000` 里的 `10000` 是手机从公网访问时使用的端口；
- Tailscale Funnel 只支持 `443`、`8443`、`10000` 三个公网端口；
- `443` 是标准 HTTPS 端口，被其他服务占用时可以改用 `10000` 或 `8443`；
- 使用 `10000` 或 `8443` 时，填回插件的地址必须带 `:10000` 或 `:8443`，并且要和命令实际使用的端口一致。

让这条 Funnel 配置在电脑上保持运行；`--bg` 表示后台运行，不需要一直留着 PowerShell 或终端窗口，但电脑关机、Tailscale 退出或关闭 Funnel 后，公网入口会失效。

这条 Funnel 是插件外面的公网入口，不是插件建立的隧道。

#### 3. 把地址填回插件

1. 打开「设置 → 遥控设置 → 连接与固定地址 → 手动公网地址」。
2. 在「公网基础地址」里填完整基础地址，例如 `https://machine.tailnet.ts.net:10000`。
3. 不要只填域名或端口，也不要在地址后面加 `/mini` 或其他路径。
4. 点「保存地址」。
5. 回到上方的「手机连接」，找到「公网（手动地址）」和对应二维码，再用手机扫码。

做完应该看到：设置页提示已保存，「手机连接」里多出「公网（手动地址）」，其他连接方式不受影响。

如果要手动检查外部入口，可以在浏览器访问 `https://你的地址:10000/mini`，至少应该看到登录页；这里的 `/mini` 只用于浏览器检查，不要填进「公网基础地址」。

#### 4. 验证是不是真的公网

这一步不能省，否则很容易把只能在 tailnet 内访问的地址误当成公网地址。

1. 在电脑上执行：

   ```powershell
   tailscale funnel status
   ```

   做完应该看到：状态里显示 `Funnel on`，并且能看到刚才配置的公网端口。

2. 在手机上彻底关闭 Tailscale，不要只在 App 里断开连接，最好把 Tailscale 从后台划掉。
3. 关闭手机 Wi-Fi，确保手机使用移动网络，再打开刚才的二维码或手动公网地址。

做完应该看到：手机不开 Tailscale、只用移动网络，也能打开遥控页面。

- 能打开，说明 Funnel 公网链路可用。
- 关掉 Tailscale 后打不开，重新打开 Tailscale 却能访问，说明刚才走的是 tailnet，不是 Funnel 公网。
- 关掉 Tailscale 后出现 TLS 握手失败或一直转圈，先按公网入口不可达处理，不要继续调插件。

#### 5. 不用时关掉 Funnel

在电脑上执行下面的命令，并把 `10000` 换成你实际开启的公网端口：

```powershell
tailscale funnel --https=10000 off
```

做完应该看到：这个公网入口不再提供访问；插件里保存的手动地址不会替你重新开启它。

### 如果你用反向代理

按你的反向代理软件，把公网 HTTPS 入口转发到插件的本机手机服务端口即可，不必照抄某一款软件的配置。

需要满足这些条件：

- 外部入口使用 HTTPS，并有有效证书；
- 转发目标是 `http://127.0.0.1:3090`，实际端口以「自检」显示为准；
- 转发时保留原始路径和查询串；
- 支持 SSE 和 WebSocket，避免页面能打开但消息不能持续更新；
- 向本机服务传递 `X-Forwarded-Proto: https`；
- 不要再加一层登录页或 Basic Auth 挡在插件自己的登录、配对和门禁前面。

做完应该看到：手机从外部网络访问 `https://你的域名/mini` 能打开页面，然后再把不带路径的基础地址填进插件。

### 常见错误

- **只填域名，没填端口**：使用 `8443` 或 `10000` 时必须带上对应端口，Funnel 也不能使用这三个之外的公网端口。
- **把 `/mini` 填进基础地址**：插件只需要 `https://machine.tailnet.ts.net:10000` 这样的基础地址，不要带 `/mini` 或其他路径。
- **443 已被占用却仍然使用 443**：改用 `10000` 或 `8443`，并同时修改 Funnel 命令和插件里的地址。
- **手机还开着 Tailscale**：这可能只证明 tailnet 内能访问，必须彻底关闭手机 Tailscale 后用移动网络再测。
- **外部入口本身打不开，却先改插件**：先确认 `tailscale funnel status` 为 `Funnel on`，并确认反向代理或 Funnel 本身可用。
- **入口停止后等插件自动恢复**：插件不探测、不修复外部入口，Funnel 或反向代理停止后，需要由你自己恢复。
- **换端口只改了一边**：如果要从被占用的 `443` 换到 `8443` 或 `10000`，Funnel 命令和插件地址要一起改；仍然不通时，可以改用 Cloudflare 命名隧道或自建中继，不要把 Funnel 当成国内稳定的固定地址。
