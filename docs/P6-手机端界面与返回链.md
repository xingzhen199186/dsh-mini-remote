# 手机端界面与返回链（2026-11-12 定稿）

这一篇收口今天所有**界面层**的改动。它回答三件事：设置页长什么样、返回怎么走、以及**哪些曾经做过又被撤掉的**（连同原因，免得以后重做）。

## 一、设置页的层次

三个**平级**的板块，各自管一件事：

| 板块 | 管什么 |
|---|---|
| **手机桥** | 手机怎么连上电脑（开关、地址、状态） |
| **屏幕操作** | 电脑能对这块屏幕做什么 |
| **手机终端** | Termux 装没装、授权没有 |
| **工作文件夹** | 电脑能在哪个文件夹里读写你的文件 |

**「屏幕操作」展开后**，里面再分三块（也是平级）：

- **无障碍**——开没开、去哪儿开；
- **确认档位**——始终免确认 / 本任务免确认 / 每次都问；
- **最近操作**——电脑最近动了什么，以及“连续 10 分钟没操作就停”的提示。

**默认收起。** 第 4 条（工作文件夹）排在最后，因为它平时不需要动。

**箭头的位置**：单独占一格固定宽度、垂直居中。以前它紧跟在状态文字后面，**状态文字一变长箭头就漂**——那是排版错，不是错觉。

## 二、返回链：交给系统，页面只负责关

**动画不是我们画的，是系统给的。** 从边缘划 = 系统返回手势，它把“返回”交给 App，App 交给页面，页面按顺序关掉最上面那层。

**关闭顺序**（先关最上面那层）：

```
子代理会话页 → 子代理列表 → 模型面板 → 添加文件/调用指令 → 文件抽屉 → 设置 → 镜像
```

**没有可关的层就什么都不做**，于是返回继续往下走（正常退出，不会卡住）。

**判断做对了**：面板开着时从边缘划一下，**只关面板、不退 App**；再划一次才退。

## 三、撤掉的东西（连同原因）

| 撤掉的 | 原因 |
|---|---|
| **全屏终端页**（含 Termux 的终端模块） | 碰不到共享存储、装不了包，却长得像“掌上 Linux”；**期待建立以后，解释成本比功能本身高**。能力保留在后台（`phone_sh`） |
| **浮动 `>_` 按钮** | 浮在网页上会压住网页自己的控件；入口挪回设置页 |
| **自绘的跟手滑动动画** | 系统已经提供了同类动画，两套一起动就是打架 |
| **`setSystemGestureExclusionRects`（挖掉左边缘）** | 为了让自绘手势收到触摸，把系统返回手势的一条边废掉了——**方向就是错的** |
| **原生子页面的 `SwipeBack`** | 连接配置/配对/扫码本来就是独立页面，系统返回天然能退回，多画一层反而乱 |

**恢复位置**：终端页那套完整可用状态在 git 提交 `51cdb94`。

## 四、几个必须记住的边界

- **命令面板/终端**：只能碰 App 自己的目录；**看不到**你选的工作文件夹（那是授权凭证，不是路径）。
- **工作文件夹**：只能有一个，靠系统选择器选；**不申请“所有文件访问”**，那是商店会驳回的权限。
- **无障碍**：读屏与点击受三档确认约束；**停止浮层**只在“正在操作手机”时出现，读状态与发通知不算。

## 五、今天的教训

**能用系统能力就别自造。** 我在这条上绕了两轮：用户说“要跟设置页一样”，我两次都自己画动画；其实答案就在设置页那十几行代码里——**它的顺滑来自系统，页面只负责关最上面一层**。

**判断“该照谁做”之前，先读那个东西的真实实现。** 凭印象动手，代价是两轮返工。

**面板关不掉时，先查它有没有登记进返回链**，而不是去加手势。
