# 本机文件能力：不装任何东西就能读写手机文件（2026-11-12 落地）

用户的要求很明确：**不能让用户为了用这个 App 再装一个 App**。所以文件能力必须做在我们自己的 App 里，不能依赖 Termux。

## 只有两种位置

| 前缀 | 是什么 | 需要什么 |
|---|---|---|
| `app:` | App 自己的私有目录 | **不需要任何权限** |
| `work:` | 用户在系统选择器里**亲手选的一个文件夹** | 选一次，授权持久化，重启后仍有效 |

**没有第三种。** 目录外的文件我们碰不到——这是系统的边界，不是我们的取舍。

## 六个工具

| 工具 | 做什么 |
|---|---|
| `phone_fs_list` | 列目录（最多 500 条） |
| `phone_fs_read` | 读文本，分页（`offset` / `limit`） |
| `phone_fs_write` | 写文件，父目录自动创建（上限 6 万字符） |
| `phone_fs_edit` | 改一行，**原文必须唯一**，否则拒绝 |
| `phone_fs_glob` | 按文件名找，支持 `*` 和 `?` |
| `phone_fs_grep` | 搜内容，返回文件 + 行号 + 那一行 |

**都跑在 App 进程里，不经过 shell、不需要 Termux。**

## 硬性上限（防止一次跑很久）

- 目录最多往下 **8** 层；
- 一次最多返回 **300** 条命中、**500** 个文件；
- 搜内容时只翻 **256KB** 以内的文件；
- 读一次最多 **20 万字符**。

超了会**如实告诉你被截断**，不会假装全部找到了。

## 为什么不用「所有文件访问」

Google Play 只允许**核心功能就是管理文件**的应用申请 `MANAGE_EXTERNAL_STORAGE`（文件管理器、杀毒、备份），而且要提交声明表单并获批，还要录屏说明为什么非它不可。

我们的核心功能是「手机遥控 / 让 AI 帮你干活」，**不是文件管理**——硬报大概率驳回，不合规还会下架。

**所以清单里绝不声明这个权限**，并且有测试钉住（`test/cross-language-constants.test.mjs`）。走自有渠道时也不必加，SAF 选择器已经够用。

## 手机端一次设置

设置 → 屏幕操作 → **工作文件夹** → **选择文件夹** → 挑一个（例如「下载」）。

**判断做对了**：那一行显示「当前：<文件夹名>」。

## 与 Termux 的关系

**不是替代，是分层**：

- **本机文件工具**：日常读写、查找、搜索，**不需要任何额外安装**；
- **Termux 终端**：真要跑脚本、装包、长任务时才用，**成了可选增强**；
- **无障碍**：界面操作，保持不变。

选路提示会随手机上「有没有可用 Termux」自动变化，用户不需要自己判断。

## 已知边界

- 碰不到**别的 App 的私有数据**（无 root，系统不允许）；
- 碰不到**没选的那个文件夹之外**的位置；
- `phone_fs_write` 会**覆盖**，不会自动备份；
- SAF 下建文件用的 MIME 是 `text/plain`，非文本文件的读写不保证。

## 踩过的坑

- **工具注册少一个括号**：`})))` 写成 `}))`，不会报错，只会让**下一个工具静静消失**。这个错误在本次实现里犯了两次，**两次都被结构性测试当场抓到**——所以那道检查值得留着。
- **`~` 不能当工作目录**（Termux 那条路）：会被当字面量 `/~`，报 `The working directory not found`。不传就用家目录。
