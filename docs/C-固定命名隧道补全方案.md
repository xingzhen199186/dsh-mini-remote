# C：固定命名隧道补全方案

## 0. 目标

把「固定地址（Cloudflare 命名隧道）」从“能连上”做到“长期不用管”，并且在故障解释、恢复控制、手机侧体验上超过参考项目。

范围只做 C：

- 用户自己的 Cloudflare 命名隧道；
- 保留快速隧道、自建 frp、Tailscale、局域网；
- 不做 A（固定 Worker 中继），不做原生 App。

## 1. 现在缺什么

| 能力 | 现在 | 补完后的目标 |
|---|---|---|
| cloudflared 异常退出 | 只报错，等用户手动重启 | 自动退避重启 |
| 公网探测失败 | 标记失败，停掉探测 | 分类后自动恢复或暂停 |
| 目标变化 | 路由层先停再起 | 指纹比较，同目标不重起 |
| 错误分类 | 一段原始日志 | 进程 / 边缘 / 域名 / 本机服务 / token 五类 |
| 重试上限 | 无 | 有恢复预算，超过后暂停并给手动按钮 |
| 本机 DNS 失败 | 可能误判隧道死亡 | 公共 DNS 交叉验证，不误杀 |
| 手机侧 | 固定地址二维码 | 故障时保留地址，明确“暂时不可用” |
| 测试 | 参数和 UI 为主 | 生命周期、退避、误判、token 失败全覆盖 |

## 2. 设计原则

1. **不照搬对方的 TunnelManager**  
   我们不复刻它的类结构、命名和状态字段；按我们自己的插件生命周期做三层状态机。

2. **先分类，再动作**  
   不是所有“连不上”都该重启。token 错、域名错、本机服务没开，重启一百次也没用。

3. **有预算的恢复**  
   自动重试是有限度的。超过预算就暂停，把决定权交回用户，避免后台无限重连。

4. **不误杀**  
   本机 DNS 坏不等于隧道坏；Cloudflare 边缘通、本机解析不了时，保留地址并提示，不把二维码收走。

5. **可解释**  
   界面不只说“失败”，要说清是哪一层失败、下一次什么时候重试、用户能做什么。

6. **可测试**  
   进程、时钟、探测、DNS 全部可注入；不靠真连 Cloudflare 才能跑测试。

## 3. 架构

新增一个独立的隧道监督器，不把逻辑继续堆在 `bringTunnelUp()` 里：

```text
lib/tunnel-supervisor.js
  TunnelSupervisor
    start(target)
    stop()
    retryNow()
    snapshot()

  target = {
    mode: 'quick' | 'named',
    port,
    token?,          // named
    publicUrl?,      // named
    binaryPath,
  }
```

职责边界：

- `tunnel.js`：只负责“起一个 cloudflared 进程”，quick/named 各一个适配器；
- `tunnel-supervisor.js`：负责状态机、退避、健康检查、错误分类、恢复预算；
- `index.js`：只负责配置、路由、配对和生命周期接线；
- 前端：只读 `snapshot()`，不自己推断状态。

## 4. 状态机

```text
idle
  → starting
      → running
          → degraded        （公网探测连续失败）
              → restarting
                  → running
                  → paused  （恢复预算用完）
          → restarting      （进程异常退出）
      → failed              （配置错误 / token 错，不重试）
  → stopped
```

对用户只暴露五个词：

```text
未开启 / 正在连接 / 已连接 / 正在恢复 / 已暂停
```

内部可以更细，界面不要给用户看十个状态。

## 5. 错误分类

每次失败先归类，再决定动作。

| 类型 | 典型现象 | 动作 |
|---|---|---|
| `config` | 缺 token、公网地址不是 https | 不重试，直接提示改配置 |
| `auth` | Cloudflare 拒绝 token、401/403 | 不重试，提示轮换 token |
| `edge` | TLS 握手失败、连不上 Cloudflare | 退避重试 |
| `dns` | 本机解析不了固定域名 | 公共 DNS 复核；不轻易判死 |
| `origin` | 隧道通，但本机 3090 没开 / 502 | 不重启隧道，提示检查本机服务 |
| `hostname` | Public Hostname 和公网地址不一致 / 404 | 不重试，提示对齐域名 |
| `unknown` | 其他退出 | 有限重试 |

## 6. 恢复策略

- 首次失败后 5 秒重试；
- 之后 10、20、40、60 秒，最大 60 秒；
- 加 ±20% 抖动，避免所有客户端同一秒重连；
- 连续 5 次失败进入 `paused`，不再自动重试；
- 稳定运行 5 分钟后，恢复预算清零；
- 用户点「立即重试」时，预算重置一次；
- `stop()` 之后绝不复活。

和对方的区别：对方主要是“失败就重启”；我们是“先分类、再在预算内重启，超预算暂停”。

## 7. 目标指纹

给目标算一个短指纹：

```text
sha256(mode + port + publicUrl + token)
```

只用于比较，不写日志、不进二维码。

规则：

- 指纹相同：不重起；
- 指纹变化：停旧目标，起新目标；
- token 不落日志，只显示“已更换”。

这样避免用户点两次保存就起出两条隧道，也避免 token 出现在诊断信息里。

## 8. 健康检查

分三层，不混成一个“失败”：

1. **进程层**：cloudflared 还活着吗；
2. **边缘层**：有没有收到 `Registered tunnel connection`；
3. **公网层**：固定 URL 能不能拿到 HTTP 响应。

探测规则：

- 每 60 秒一次；
- 连续 2 次失败才算 `degraded`；
- 单次超时不立刻判死；
- 本机 DNS 失败时，用 `1.1.1.1` / `8.8.8.8` 做一次交叉解析：
  - 公共 DNS 能解析：只提示“本机 DNS 有问题”，不重启；
  - 公共 DNS 也解析不了：才按 `edge` 或 `hostname` 处理。

## 9. 后端接口

`GET /mini-remote/pairing` 里的 `tunnel` 增加：

```text
phase: idle | starting | running | degraded | restarting | paused | failed
mode
publicUrl
hasToken
attempts
nextRetryAt
lastErrorKind
lastError
```

`POST /mini-remote/tunnel` 支持：

```text
{ enabled, mode, namedToken, publicUrl, action? }
action = save | start | stop | retry
```

兼容旧请求：只有 `{enabled}` 时仍按当前模式处理。

## 10. 前端

固定地址卡片按状态显示：

```text
未配置：填公网地址和 token
正在连接：转圈 + 说明首次约 30 秒
已连接：绿色 + 固定地址
正在恢复：黄色 + “N 秒后自动重试” + 立即重试
已暂停：红色 + 最近错误 + 立即重试
配置错误：红色 + 具体改哪一格
```

保留：

- 可展开六步配置指引；
- token 密码框、不回显；
- 公网地址复制；
- Cloudflare 明文提示；
- 手机二维码「公网（固定）」。

新增：

- 「立即重试」按钮；
- 「最近一次错误」可展开，默认收起；
- 恢复倒计时；
- 失败类型一句话，不直接甩原始日志。

## 11. 测试与验收

### 单元测试

- 同目标重复启动不重复起进程；
- 目标变化会停旧起新；
- 进程异常退出后按退避重启；
- 连续失败达到预算后进入 paused；
- `stop()` 后不再重启；
- token 错不进入无限重试；
- 本机 DNS 失败、公共 DNS 正常时不判死；
- 公网 502 归类为 origin，不重启隧道；
- token 不出现在 argv 和日志。

### 客户端测试

- 五种状态各自文案；
- 倒计时和「立即重试」；
- 配置指引默认收起；
- token 输入框不回显；
- 固定地址二维码只在配置完成时出现。

### 真机验收

1. 手动结束 cloudflared，10 秒内自动恢复，固定地址不变；
2. 断网 30 秒再恢复，状态从“正在恢复”回到“已连接”；
3. 填错 token，不反复重试，提示 token 无效；
4. 停掉本机 3090，显示“本机服务没开”，不误重启隧道；
5. 手机在恢复后不用重新扫码；
6. 快速隧道、自建 frp 不受影响。

## 13. 我们比对方多什么

不是功能数量堆叠，而是三件事：

1. **故障分类**：对方主要保证“会重启”；我们先判断“该不该重启”。
2. **恢复预算**：对方可能一直重试；我们会在预算用完后暂停，把控制权交回用户。
3. **不误杀**：本机 DNS 坏时保留地址，不让用户白扫一个被收走的码。

这三件事，才是“长期无人值守”和“看起来能跑”的区别。
