# 手机终端：在 Termux 里干活（2026-11-12 落地）

电脑可以在**手机上的 Termux** 里执行真正的命令，并且读写手机上的文件。这条路走**现有的手机桥**，所以内网、Tailscale、自建中继、隧道**四条线都通**，不用新开端口，也不用把手机暴露到公网。

## 一句话说清两条路的分工

- **动界面**（点、滑、输入、返回、打开 App、亮屏、读屏、截图）→ 还是无障碍那条路，**没有变**；
- **动文件、跑命令**（找文件、读文件、改文件、装包、批处理）→ 优先走终端这条路。

判断依据是**手机每次心跳上报的 `termux` 标记**：装了 Termux 且授权了才算可用。可用时模型被告知优先用终端；不可用时明确被告知**不要调** `phone_shell`。

## 为什么手机侧只需要认识少数几个动作

读文件、写文件、改文件、找文件、搜内容，**都是在电脑这侧翻译成 bash 命令再发出去的**，手机上只看到一条命令。所以：

- 手机端只认**本地真的要执行**的那些动作；
- 以后再加这类文件工具，**不用重新装 App**，改电脑端就生效。

## 工具清单

| 工具 | 做什么 | 参数要点 |
|---|---|---|
| `phone_shell` | 执行一条命令 | `command`；可选 `workdir`、`stdin`、`background`、`timeoutSeconds` |
| `phone_shell_output` | 看后台任务跑到哪、还在不在跑 | `job`（发起时拿到的编号） |
| `phone_shell_stop` | 停掉后台任务（含子进程） | `job` |
| `phone_read` | 读文件，分页 | `path`、`offset`、`limit` |
| `phone_write` | 写文件（覆盖，自动建目录） | `path`、`content` |
| `phone_edit` | 改文件，原文必须唯一 | `path`、`old`、`new` |
| `phone_glob` | 按文件名找 | `pattern`、`dir` |
| `phone_grep` | 搜文件内容 | `pattern`、`path` |

**长任务必须用后台**：装包、下载、批处理动辄几分钟。同步等一定超时，而超时之后**命令还在手机里继续跑**，电脑却以为失败，会重跑——重复安装、重复删除就是这么来的。`background: true` 立刻返回编号，之后查进度、必要时叫停。

## 手机端一次性设置

1. Termux 里打开对外执行：`echo 'allow-external-apps = true' >> ~/.termux/termux.properties`，然后**彻底关掉 Termux 再打开**。
2. 给 App 授权：**App 设置 → 屏幕操作 → 手机终端 → 去授权**，系统弹出**带「允许 / 拒绝」**的框，选允许。

**判断做对了**：App 里那一行变成「已授权，可以在手机上执行命令」。

## 三个必须知道的边界

**一、设置页里那个权限说明弹窗不会授权。** 它只有「知道了」，点完权限仍然是没给。**必须由 App 自己发起请求**（就是上面第 2 步那个按钮），系统才会弹真正的授权框。我们为此专门加了「手机终端」那一行。

**二、不要给命令传工作目录 `~`。** 它会被当成字面量 `/~`，Termux 报 `The working directory not found at path "/~"`，命令根本没跑。**不传就是家目录**，要指定就写绝对路径。

**三、结果字段名是 `stdout` / `stderr` / `errmsg`，不是带长前缀的名字。** 解析按"包含"匹配，并且跳过带 `length` 的字段；正常时 `errmsg` 会传成字符串 `"null"`，那不算错误。

## 安全

这是**任意命令执行**，破坏力比点屏幕大一个量级。它和点屏幕**受同一套三档确认约束**，没有额外特权，也没为它单独编"永远确认"的规矩——按用户定的口径，确认就是设置里那三档。

## 落地时的坑（写给以后的自己）

- **工具注册少一个括号不会报错**，只会让**下一个工具静静消失**。已加结构性测试：注册调用数不得少于工具数，且禁止 `},` 后直接跟 `{ name: 'phone_...'` 的形状。
- **两边靠字符串约定的东西要摆在一起核对**（动作名、通知类型）。打错一个字母不会报错，只会永远不生效。已有的对照测试只比"真发给手机的那些"，因为文件工具是电脑侧封装的。
- **改完电脑端要真重启才生效。** 有一次连说三次"重启了"，实际后台进程还是旧版本——表现是"新工具不存在"。判断办法：`phone_read` 这种新工具能不能调出来，能调出来才是真重启。
